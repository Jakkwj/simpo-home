# CLI and Skills releases

CLI releases use `X.Y.Z`. All four public Skills share an independent `X.Y.Z`
bundle version, starting at `1.0.0`. The private Web package also starts at
`1.0.0` and advances separately when only Web content changes. A Skills-only
change does not require a new CLI installer. The independent `cli_min_version`
field describes compatibility; Skills `1.0.0` requires CLI `0.1.9` or later.
Compare version components numerically. Historical `X.Y.Z-skills.N` releases
remain supported by the new CLI and sort before a stable release at the same
`X.Y.Z`.

The updater uses the public catalog at
`https://raw.githubusercontent.com/Jakkwj/simpo-home/master/plugins/simpo/releases/index-v2.json`
(schema 2, containing both independent and historical Skill versions).
The legacy `index.json` stays at schema 1 and contains only `X.Y.Z-skills.N`
Skills so CLI 0.1.8 keeps working. The release builder synchronizes published
CLI installer entries to **both** catalogs, allowing old clients to upgrade.
CLI 0.1.9 falls back to the legacy catalog only if the new URL returns HTTP 404.
Skills ZIPs live beside that catalog. CLI installers keep the existing Gitee
`package` release URLs used by the website. All artifacts include SHA-256 and
size; downloads require HTTPS. The CLI does not query an update service during
ordinary commands and never sends an API Token to release hosts.

## Skill sources and versions

All editable Skill sources now live in the private `SimpoSkills` repository.
`plugins/simpo/skills/`, `release.json`, and `generated.json` are generated public
artifacts. Do not edit them by hand or copy Web instructions into this repository.

Maintain public package `version` and `cli_min_version` in
`SimpoSkills/targets/cli-public.json`. Run in that checkout:

```bash
python3 tools/build.py --target cli-public
python3 tools/check.py --target cli-public --dist
python3 tools/export.py --target cli-public --home-root /path/to/SimpoHome
python3 tools/export.py --target cli-public --home-root /path/to/SimpoHome --check
```

SimpoSkills builds directory artifacts only. After export, this repository's
`plugins/simpo/tools/build_release.py` is the sole ZIP packaging entrypoint;
release archives are stored in `plugins/simpo/releases/`.

| File | Version maintenance |
| --- | --- |
| `SimpoSkills/targets/cli-public.json` | Maintainer sets public version and CLI compatibility. |
| `plugins/simpo/release.json` | Generated by the private source exporter. |
| `.claude-plugin/marketplace.json` | Release builder synchronizes the plugin version. |
| `plugins/simpo/.claude-plugin/plugin.json` | Release builder synchronizes the plugin version. |
| `plugins/simpo/releases/index-v2.json` | Full release history, URL, size, SHA-256, and compatibility. |
| `plugins/simpo/releases/index.json` | Legacy Skills history and synchronized CLI installer entries. |

Web-only changes use an independent internal version and do not require a public
release. Public content changes increment the Skill package version; previously
published ZIPs and catalog entries remain immutable.

## Publish Skills

1. Finish and test source changes in SimpoSkills, increment the affected version,
   and export the `cli-public` target as above.
2. From the SimpoHome repository root:

   ```bash
   python3 plugins/simpo/tools/build_release.py
   python3 -m unittest discover -s plugins/simpo/tools -p 'test_build_release.py'
   ```

3. Review the generated Skills, `generated.json`, `release.json`, new ZIP/catalog,
   `.claude-plugin/marketplace.json`, and `plugins/simpo/.claude-plugin/plugin.json`.
   Commit these public artifacts together and publish through the normal release
   process. The private source repository is never pushed here.

The release builder validates all exported checksums and rejects unexpected
files in the public Skill tree. It needs only the public artifacts, so downstream
users do not need access to SimpoSkills. Building/exporting itself does not push,
deploy, or update installed user Skills. Keep previous release ZIPs and catalog
entries. A Skills-only release needs no CLI rebuild or `--cli-version` argument.

For the `1.0.0` transition, first build, test, upload, and announce CLI `0.1.9`
installers for the supported platforms. Keep both catalogs and historical ZIPs
when publishing `1.0.0`. CLI 0.1.8 users run `simpo update` first, then
`simpo skills update --target codex` (or `claude`) using the new CLI. Preparing
the catalogs locally does not mean a CLI 0.1.9 installer is available online.

The old `sync_dataset_skill.py` is a compatibility wrapper for exporting the
private `web-internal` target. It no longer derives Web instructions from these
public artifacts and requires a private SimpoSkills checkout.

## Publish CLI

1. Update `SimpoClient/client/source/cli/config.py`, both CLI builder configs,
   and the Inno Setup fallback version. Build/test the production installers
   using `SimpoClient/client/builder/cli/README.md`. New private modules must be
   included in **both** builders' `CLI_PACKAGE_MODULES` lists.
2. Upload validated production `.deb` / `.exe` files to the existing Gitee
   `Jakkwj/simpo-home` release named `package`. Verify the public download URLs
   against the local files. Never announce an installer before uploading it.
3. Explicitly announce the uploaded version (the script reads local artifacts):

   ```bash
   python3 plugins/simpo/tools/build_release.py --cli-version 0.1.9
   ```

   Default installer directory: `resource/cli`. Override with `--cli-directory`.
   Only available platforms for the selected version are added. A later run can
   add the second platform without changing the first one's checksum. CLI
   builds alone do not alter the catalog. Development installers are excluded.
4. Update website download links when ready; commit and push the generated
   catalog after upload. A platform keeps its last published version until its
   own newer artifact is announced.

## Client behavior

```bash
simpo update --check
simpo update
simpo skills list --target codex
simpo skills install --target codex
simpo skills update --target codex --check
simpo skills update --target codex
simpo skills install --target claude
```

CLI update supports Debian/Ubuntu amd64 and Windows x64. Linux runs `dpkg`
through `sudo` when needed and verifies the installed version. Windows returns
`scheduled`, then a detached system PowerShell waits for the CLI/Python launcher
to exit, starts Inno Setup with UAC elevation, and verifies the new CLI. Check
the returned `status_file` (`installed` / `failed`) and `installer_log`; scheduling
is not a successful-install claim. Windows PowerShell is required. No automatic
restart or forced termination of other applications is requested.

Skills install/update requires an explicit target. Codex respects `CODEX_HOME`;
Claude respects `CLAUDE_CONFIG_DIR`. Defaults are `~/.codex/skills` and
`~/.claude/skills`. `claude-code` is accepted as an alias for `claude`. Installing
Project adds its three dependencies. With no names, install selects all four;
update selects installed Skills and their Project dependencies. `--version`
selects a published version; downgrades are refused. If the latest Skills
require a newer CLI, upgrade the CLI or select a compatible Skills version.

Existing manual/Skill Installer installations are unmanaged. To migrate, use
`simpo skills install --target codex --force` (or `claude`); the returned backup
directory retains the original files. Updates reject modified files unless
`--force` is supplied. Files are staged/validated first; all replacements roll
back on an ordinary installation failure. Replaced unmodified files are removed,
including scripts deleted in the new bundle. Per-target directory locks prevent
concurrent Skills updates; a hard-killed process may leave a lock requiring
manual removal and a backup directory to recover. Start a new assistant session
after changing Skills.

Claude Marketplace installations remain managed through Claude's `/plugin`
manager. The CLI reports a registered `simpo@…` plugin and refuses local
installation alongside it; uninstall the plugin first to switch to local
Skills. Local Skills use `/simpo` and `/simpo-create-project`, while the plugin
uses `/simpo:simpo` and `/simpo:simpo-create-project`.
