update-biomodel：修改 Draft BioModel

使用 JSON 模型表替换一个属于当前用户的 version=0 Draft BioModel。后端会 重新解析提交的表格，并重新计算 Balance、替换名称和表格数量 等派生字段。

这个命令不会删除 BioModel，也不会修改 BioModel 记录本身的名称。标识发生变化时， 后端会比较保存前的 Draft 和提交的 JSON，自动生成网页端使用的 changeValueBioModel 字典。Release 和 Standard 版本是不可变版本，不能通过此命令修改。

使用条件​

  • Token scope：write
  • BioModel 必须属于当前 Token 用户。
  • BioModel 必须是 state=Draft 且 version=0。
  • JSON 必须包含 Component、Parameter 和 Matrix 数组。
  • Composition 和 Ionization 可选。
  • Balance 是只读派生表，禁止提交。

命令格式​

simpo update-biomodel BIOMODEL_ID --json MODEL.json [OPTIONS]

JSON 格式与 create-biomodel 相同。可以先使用 get-biomodel 获取 JSON，修改后删除只读的 Balance 表，再提交更新。

选项​

选项默认值作用
BIOMODEL_ID必填当前用户拥有的 version=0 Draft BioModel ID
--json FILE必填UTF-8 JSON 模型表文件，最大 20 MiB
--description TEXT保留原值替换 Markdown 描述
--sourcepaper-id INTEGER保留原值替换来源论文 ID
--timeout SECONDS3700.0解析和 HTTP 请求的最长等待时间
--api-token TOKEN已配置 Token临时覆盖完整 Token
--base-url URL安装包环境对应的地址仅覆盖本次请求的后端地址

此命令不提供名称参数。因为名称参与 Draft/Release 版本身份和 Project 引用， 重命名应设计为单独的安全操作。

标识改名​

不需要额外提供映射文件。更新接口会比较当前 Draft 与提交的 JSON，自动生成网页端 使用的 changeValueBioModel（最终名称 -> 原始名称）字典，保留兼容的 Project 值； Component 改名还会同步匹配的 Ionization.Symbol 单元格。

如果有 Project 使用这个 Draft，后端会立即重新生成每个关联 Project。仍然兼容的 用户输入（Variable、Conversion、 Activator、Target 和 Weight）会被保留；新增或不兼容的字段会按照新的 BioModel 结构生成。返回字段 affectedProjectCount 表示实际同步的 Project 数量。 受影响 Project 中已有的 Simulation、Sensitivity、Uncertainty 和 Estimation 结果 会被标记为需要重新计算。

返回结果​

{
  "success": true,
  "id": 123,
  "name": "TestModel",
  "state": "Draft",
  "privacy": "Private",
  "version": 0,
  "description": "updated",
  "sourcepaperId": null,
  "amountParameter": 4,
  "amountComponent": 3,
  "amountRate": 2,
  "amountComposition": 1,
  "affectedProjectCount": 2
}
