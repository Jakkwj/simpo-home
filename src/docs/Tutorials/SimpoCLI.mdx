# SimpoCLI command-line guide

`SimpoCLI` is the command-line interface for the SIMPO OpenAPI. It manages the
complete Draft, synchronization, and Release lifecycle for BioModels, DataSets,
and Projects; reads and updates Project Variables; prepares calculations; starts
the locally installed `SimpoClient`; monitors or stops calculations; and reads
large stored results in bounded pages.
Its terminal command is the short, lowercase `simpo`.

This page is the complete SimpoCLI command index. Each command also has its own
page in the collapsible **SimpoCLI** section.
Every command supports `--help` when syntax is unclear or a usage error occurs.
Ordinary operations can run directly; the backend checks permissions.

For AI assistant integrations, see the [SIMPO Skills overview](./SimpoCLI/simpo-skills)
for the complete Codex and Claude Code directory, invocation names, installation
paths, and detailed guides.

| Skill | Purpose |
| --- | --- |
| [`simpo`](./SimpoCLI/simpo-cli-skill) | Operate the CLI and read its JSON results. |
| [`simpo-create-biomodel`](./SimpoCLI/biomodel-skill) | Build a model from a paper or explicit user-defined equations. |
| [`simpo-create-dataset`](./SimpoCLI/dataset-skill) | Build a DataSet from design inputs, source tables, or calibrated figure data. |
| [`simpo-create-project`](./SimpoCLI/paper-to-project-skill) | Reuse both extraction workflows to create linked resources and test paper reproduction. |

These are assistant Skills, not additional terminal subcommands. Use
`$simpo-create-project` in Codex or `/simpo:simpo-create-project` in the
Claude Code plugin.

### Skill tool dependencies

The regular `simpo` commands do not require user-installed Python or Poppler.
The DataSet and Project paper-figure workflow uses the bundled helpers only
when PDF pages still need rendering: Python 3 is required for the helpers and
Poppler's `pdftoppm` is required for PDF rendering. `pdfinfo` is optional when
the page range is supplied. Text, tables, supplied images, and supplied
digitizer exports do not require these tools. The workflow checks
`python3 --version` and `pdftoppm -v` before rendering and pauses with an
installation or equivalent-renderer option when either is unavailable.

## Prerequisites

- A SIMPO account and an OpenAPI Token created on the Dashboard's **API Tokens**
  page.
- The minimum Token scope required by the command:
  - `read`: list and read owned BioModels, DataSets, and Projects, read Project
    Variable fields, and retrieve stored calculation results;
  - `write`: create, update, synchronize, or release BioModels, DataSets, and
    Projects, and update a Variable field in a version `0` Draft Project;
  - `calculate`: prepare, inspect, or stop a calculation.
- The [`calculate`](./SimpoCLI/calculate) command additionally requires
  the matching platform version of `SimpoClient` on the same computer.

## Download and install

SimpoCLI is independent from SimpoClient, but the `calculate` command
starts SimpoClient to perform the actual local calculation. Install both
applications if this computer will run calculations.

## Obtain your personal API Token

1. Sign in to the SIMPO Dashboard.
2. Open <a href={config.customFields.urlDashApiTokens} target="_blank" rel="noopener noreferrer"><strong>Account → API Tokens</strong></a>.
3. Select **Create Token**.
4. Enter a recognizable name, choose an expiry from `1` to `365` days, and
   grant only the scopes you need:
   - `read` for all `get-*` commands, including paginated
     `get-calculation-result` retrieval;
   - `write` for BioModel, DataSet, and Project create/update/sync/release commands, and `set-project-variable`;
   - `calculate` for calculation preparation, status, and stop commands.
5. Select **Create Token**, then immediately copy the complete Token from the
   **Token Created** dialog.

:::warning Copy the complete Token now

For security, the complete Token is displayed only once. The Token list later
shows only `tokenPrefix`, which cannot authenticate API requests. If the secret
is lost, revoke that Token and create a new one. Do not use a Dashboard login
JWT as an OpenAPI Token.

:::

## Configure and verify the Token

Save the copied personal Token and verify it before accessing a Project:

```text
simpo configure
simpo me
```

To remove only the saved API Token while keeping the CLI data directory, run:

```text
simpo logout
```

Token lookup order is:

1. the command's `--api-token` option;
2. the `SIMPO_API_TOKEN` environment variable;
3. the per-user `SIMPO_API_TOKEN.json` file.

The saved file is `~/.SimpoCLI/SIMPO_API_TOKEN.json` on Linux and
`%APPDATA%\SimpoCLI\SIMPO_API_TOKEN.json` on Windows. Protect this file;
it contains the complete secret Token.

For the complete configuration procedure, see [`configure`](./SimpoCLI/configure).

## Command reference

Each resource follows the same basic rule: edit a version `0` Draft, use a
published Release as an immutable snapshot, and use `sync-*` to copy a Release
back to its Draft. The update pages describe dependent Project rebuilding and
stale calculation results where those rules apply. Use the tables below as the
complete command directory.

### Token

| Command | Purpose | Required scope |
| --- | --- | --- |
| [`configure`](./SimpoCLI/configure) | Validate and save an OpenAPI Token | none for the local action; Token validation must succeed |
| [`me`](./SimpoCLI/me) | Verify the Token and show its identity and scopes | authenticated Token |
| [`logout`](./SimpoCLI/logout) | Remove the locally saved Token file without revoking the server Token | none |

### BioModel

| Command | Purpose | Required scope |
| --- | --- | --- |
| [`create-biomodel`](./SimpoCLI/create-biomodel) | Create a blank, Excel-based, or JSON-based Draft BioModel | `write` |
| [`get-biomodels`](./SimpoCLI/get-biomodels) | List metadata for your BioModels | `read` |
| [`get-biomodel`](./SimpoCLI/get-biomodel) | Read one BioModel and its complete model tables | `read` |
| [`update-biomodel`](./SimpoCLI/update-biomodel) | Replace the tables of a version `0` Draft BioModel | `write` |
| [`sync-biomodel`](./SimpoCLI/sync-biomodel) | Copy an owned Release/Standard version to its same-name Draft | `write` |
| [`release-biomodel`](./SimpoCLI/release-biomodel) | Create the next immutable Release from a version `0` Draft | `write` |

### DataSet

| Command | Purpose | Required scope |
| --- | --- | --- |
| [`create-dataset`](./SimpoCLI/create-dataset) | Create an empty or JSON-based Draft DataSet | `write` |
| [`get-datasets`](./SimpoCLI/get-datasets) | List metadata for your DataSets | `read` |
| [`get-dataset`](./SimpoCLI/get-dataset) | Read one DataSet and its complete model tables | `read` |
| [`update-dataset`](./SimpoCLI/update-dataset) | Replace a Draft DataSet and rebuild dependent Projects | `write` |
| [`sync-dataset`](./SimpoCLI/sync-dataset) | Copy an owned Release to its same-name Draft | `write` |
| [`release-dataset`](./SimpoCLI/release-dataset) | Create an immutable Release from a Draft | `write` |

### Project

| Command | Purpose | Required scope |
| --- | --- | --- |
| [`create-project`](./SimpoCLI/create-project) | Create a Draft from a BioModel and DataSet, with optional Solution JSON | `write` |
| [`get-projects`](./SimpoCLI/get-projects) | List owned Project metadata with BioModel/DataSet references | `read` |
| [`get-project`](./SimpoCLI/get-project) | Read one Project and its complete Solution detail | `read` |
| [`update-project`](./SimpoCLI/update-project) | Replace a Draft Project's Solution detail | `write` |
| [`sync-project`](./SimpoCLI/sync-project) | Copy an owned Release to its corresponding Draft | `write` |
| [`release-project`](./SimpoCLI/release-project) | Create an immutable Project Release | `write` |
| [`get-project-variables`](./SimpoCLI/project-variables) | Read every field in the Solution Variable table | `read` |
| [`set-project-variable`](./SimpoCLI/set-project-variable) | Update one Variable field in a Draft Project | `write` |

### Calculation

| Command | Purpose | Required scope |
| --- | --- | --- |
| [`calculate`](./SimpoCLI/calculate) | Prepare a calculation and start SimpoClient | `calculate` |
| [`get-calculation-status`](./SimpoCLI/get-calculation-status) | Read current calculation status | `calculate` |
| [`get-calculation-result`](./SimpoCLI/get-calculation-result) | Select and page stored calculation result series without an unbounded response | `read` |
| [`stop-calculation`](./SimpoCLI/stop-calculation) | Stop a calculation and matching local processes | `calculate` |

## Output contract

- Successful results are formatted JSON on **stdout**.
- Progress and errors are written to **stderr**.
- Exit code `0` means success; a non-zero code means the command failed.
- HTTP errors contain the status code and a safe backend message. `401` usually
  indicates an invalid, expired, revoked, or environment-mismatched Token;
  `403` indicates a missing scope.

This makes stdout safe to parse in automation:

```bash
result="$(simpo get-project-variables 706)" || exit $?
printf '%s\n' "$result"
```

Use `--base-url` only for a one-command development override, for example:

```text
simpo me --base-url http://127.0.0.1:8888
```

The Token must belong to the selected backend environment.
