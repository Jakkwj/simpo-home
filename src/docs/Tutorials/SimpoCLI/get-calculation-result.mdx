# `get-calculation-result`

To use balance analysis in the Dashboard, start with the
[Balance Analysis guide](../Project/BalanceAnalysis): it explains how to obtain
results, where to open them, and how to interpret the diagrams and diagnostics.
This page documents command-line retrieval of saved results.

Read a completed Project calculation result through a bounded JSON response:

```text
simpo get-calculation-result PROJECT_ID [OPTIONS]
```

Useful options are `--engine ENGINE`, `--section PATH`, `--offset N`, `--limit N`,
`--output FILE`, `--timeout SECONDS` (default `30.0`), `--api-token TOKEN`, and
`--base-url URL`. Saved Balance results additionally support `--view`,
`--dimension`, `--key`, and `--tank` through the same command.

## Read raw results

Read a large result progressively:

```text
# 1. List available engines; result values are not returned yet.
simpo get-calculation-result PROJECT_ID

# 2. List the selected engine's top-level sections.
simpo get-calculation-result PROJECT_ID --engine Simulation

# 3. Select one specific result series with a dotted path and read it by page.
simpo get-calculation-result PROJECT_ID \
  --engine Simulation \
  --section Tank1.Predicted.S_NH \
  --offset 0 --limit 1000 \
  --output result-page.json
```

The `--section` path selects a nested result step by step. For example,
`Tank1.Predicted.S_NH` means: open `Tank1`, then `Predicted`, then read the
`S_NH` result series. The returned `data` contains the requested page of that
series; users do not need to understand the result's internal tree structure.

Engine aliases such as `SIM`, `OAT_AR`, `LHS`, or `GA` are also accepted when
they correspond to a stored result family. The response includes `kind`, `mode`,
`total`, `offset`, `limit`, `hasNext`, and the current page in `data`. Continue
with a larger offset while `hasNext` is true. If a page is still too large,
reduce `--limit` or select a deeper `--section` path. Use `--output` so a terminal
or chat does not need to hold the result page.

The command reads stored result JSON only; it does not expose the internal
Project pickle. The backend still checks ownership and the Token's read scope.

## Raw result response

First list the stored result engines without downloading their values:

```json
{
  "success": true,
  "projectId": 789,
  "projectName": "MyProject",
  "projectVersion": 0,
  "engine": null,
  "section": null,
  "kind": "object",
  "mode": "engines",
  "offset": 0,
  "limit": 1000,
  "total": 1,
  "hasNext": false,
  "data": [
    {"name": "Simulation", "kind": "object"}
  ]
}
```

A selected result series returns only the requested page:

```json
{
  "success": true,
  "projectId": 789,
  "projectName": "MyProject",
  "projectVersion": 0,
  "engine": "Simulation",
  "section": "Tank1.Predicted.S_NH",
  "kind": "array",
  "mode": "values",
  "offset": 0,
  "limit": 3,
  "total": 1200,
  "hasNext": true,
  "data": [1.2, 1.1, 1.0]
}
```

## Read saved Balance results

Balance views require **SimpoCLI 0.1.10 or later and a compatible backend**.
Use `--engine SIM` or `--engine Simulation` with one exact Balance section:

| Section | Accounting scope |
| --- | --- |
| `steady_state_balance` | Rates from the saved steady-state snapshot, using each item's returned unit |
| `dynamic_balance` | Cumulative quantities over the entire saved dynamic interval, including inventory change |

For `steady_state_then_dynamic`, the dynamic interval excludes the preceding
steady-state iterations. Reading a Balance view does not run a calculation,
change the Fortran result, reintegrate saved series, or reconstruct missing
accounting data from the current model.

### Start with the summary and diagnostics

```text
# 1. Read one page of the saved steady-state summary.
simpo get-calculation-result PROJECT_ID --engine SIM \
  --section steady_state_balance --view summary --limit 10

# 2. Read the dynamic summary when that is the scope to analyze.
simpo get-calculation-result PROJECT_ID --engine SIM \
  --section dynamic_balance --view summary --limit 10

# 3. Read items requiring attention in the same dynamic scope.
simpo get-calculation-result PROJECT_ID --engine SIM \
  --section dynamic_balance --view diagnostics --offset 0 --limit 10 \
  --output balance-diagnostics.json
```

First check `balance.available`, `balance.reason`, and `balance.warnings`.
Then use the returned `dimension` and `key` to select an accounting item.
The following `Component`, `S_NO2`, and `Tank1` values are examples; use the
exact identifiers returned for your Project.

```text
# 4. Narrow the summary to one accounting item.
simpo get-calculation-result PROJECT_ID --engine SIM \
  --section dynamic_balance --view summary \
  --dimension Component --key S_NO2

# 5. Explain its external flows, reaction, physical, constraint, and inventory terms.
simpo get-calculation-result PROJECT_ID --engine SIM \
  --section dynamic_balance --view terms \
  --dimension Component --key S_NO2 --offset 0 --limit 10

# 6. Read the reaction totals by tank, then the individual reactions of a tank.
simpo get-calculation-result PROJECT_ID --engine SIM \
  --section dynamic_balance --view tanks \
  --dimension Component --key S_NO2 --offset 0 --limit 10

simpo get-calculation-result PROJECT_ID --engine SIM \
  --section dynamic_balance --view reactions \
  --dimension Component --key S_NO2 --tank Tank1 \
  --offset 0 --limit 10 --output balance-reactions.json

# 7. When reported, locate negative or non-finite concentration evidence.
simpo get-calculation-result PROJECT_ID --engine SIM \
  --section dynamic_balance --view concentrations \
  --dimension Component --key S_NO2 --offset 0 --limit 10
```

Use `--section steady_state_balance` in the same queries for saved steady-state
accounting. Each command retrieves one page; continue while `hasNext` is true
before claiming to have inspected all items or summed all details.

### Views and filters

| `--view` | Returned rows |
| --- | --- |
| `summary` | Totals, signed residual, absolute and relative differences, tolerances, status, and detail availability for each accounting item |
| `diagnostics` | Accounting items requiring attention, with reasons, severity, and differences; global warnings remain in `balance.warnings` |
| `terms` | Contributions from boundary flows, reactions, physical exchange, Constraints, and inventory |
| `tanks` | Reaction production, consumption, and net contribution grouped by tank; this is not a complete balance of each tank |
| `reactions` | Reaction production and consumption broken down by tank and Reaction |
| `concentrations` | Saved negative or non-finite concentration evidence, with Component, tank, and available type, time, and value details |

| Option | Rules |
| --- | --- |
| `--view` | Required when using any Balance filter; accepts the six values above |
| `--dimension` | Exact `Composition`, `Component`, or `Target` |
| `--key` | Exact, case-sensitive accounting item name; requires `--dimension` |
| `--tank` | Optional exact, case-sensitive tank name; only for `terms`, `tanks`, `reactions`, and `concentrations` |
| `--offset` | Zero-based offset in the filtered view; default `0` |
| `--limit` | Maximum returned rows; default `1000`, allowed range `1`–`10000` |
| `--output` | Write this response page as JSON to a file instead of stdout |

`summary` and `diagnostics` allow no filters, a dimension, or a dimension and
key. All four detail views require **both `--dimension` and `--key`**. Key and
tank names must be nonblank and at most 512 characters; quote names containing
spaces. Dots in these names are literal characters, unlike the dotted raw
`--section` path. A Balance view uses the exact section name, with no appended
path.

Pagination limits rows in the selected view, not time points or the accounting
interval. A page must fit within 5 MiB. Start with `--limit 5` or `10`, then narrow
the selection or reduce the limit if the response is too large. Without any
Balance options, the existing raw result navigation remains available.

### Interpret the response

Balance responses keep the ordinary Project and pagination fields, with
`kind="array"`, `mode="values"`, and these additional fields:

| Field | Meaning |
| --- | --- |
| `selection` | Confirmed `view`, `dimension`, `key`, and `tank` filters |
| `balance` | Saved accounting availability, scope, global warnings, interval, integration method, sample count, tolerances, and available dimensions |
| `data` | Current page of rows in the requested view |
| `data[].detail_availability` | In summary/diagnostic rows, whether each detail array was saved |
| `balance.details_available` | In a detail view, whether its array was saved; `details_reason` explains missing data |

The displayed order is `Composition`, `Component`, then `Target`, preserving
the original order within each dimension. Empty Composition rows are hidden.
A Target recorded as an identity mapping to an available Component is also
hidden: a single nonzero Conversion coefficient of `1` denotes the same item,
even when the names or unit labels differ. `balance.aliases` records these
mappings. Nonidentity Targets remain available.

Keep these distinct cases separate:

- `balance.available=false` means that the Balance snapshot is unavailable,
  unsupported, or invalid; inspect `balance.reason`. It does not mean zero
  quantities or no anomalies. Older results may have no Balance snapshot.
- Explicitly selecting a hidden item returns an empty page with
  `balance.selection_reason="empty_composition_hidden"` or
  `"identity_target_hidden"`. The latter also returns `balance.alias`; query
  its Component instead. These are not zero-valued results.
- `balance.details_available=false` means the selected detail was not saved.
  The reason is `terms_details_not_saved`, `tanks_details_not_saved`,
  `reactions_details_not_saved`, or `concentration_details_not_saved`.
  An actually saved empty array has `details_available=true`.
- An empty diagnostics page is not sufficient evidence that everything is
  clear: check `balance.available`, pagination, and `balance.warnings` too.
  Global sampling warnings are independent of item-level differences.

`success=true` confirms retrieval, not scientific closure. Keep the saved
`assessment` and use `display_assessment`, `severity`, `issues`, convergence,
and constraint information together when explaining a result.

### Units, differences, and reaction analysis

Use each summary row's `unit`. Steady-state accounting normally reports rates;
dynamic accounting reports cumulative quantities over the saved interval.
Detail rows include `dimension`, `key`, and `quantity_unit` for context. Native
detail units, especially concentration units, retain their own meaning: a
concentration in `mg/L` is not an integrated mass in `kg`.

Preserve the signed `residual`. `absolute_difference` is its absolute value;
`relative_difference` preserves `relative_error` as a ratio. Multiply that ratio
by 100 only when displaying a percentage. Explain the denominator using the
saved `closure_denominator`; do not label a balance difference as a concentration
error. `absolute_tolerance` uses the quantity's unit and `relative_tolerance` is
a ratio. For the total-source/total-sink accounting convention, closure is tested
as follows:

```text
abs(residual) <= max(absolute_tolerance,
                    relative_tolerance * (total_input + total_output))
```

Full accounting includes boundary flows, net reaction, physical exchange,
Constraints, and inventory. Reaction analysis shows production and consumption;
they need not be equal. Do not add gross reaction totals to a full balance that
already includes their net contribution. The `tanks` view groups these reaction
contributions; it does not include all transfers needed for a single tank's
complete mass balance. A batch can be analyzed through its initial and final
inventory even without influent. These views do not trace the final destination
of material originating in one particular influent.

`water_input` and `water_output` are quantities carried across the system's
water-flow boundary. `physical_input` and `physical_output` describe recorded
physical exchange such as gas transfer. `constraint_input` and
`constraint_output` are compensating sources or sinks needed for a Constraint;
`contains_inferred_constraint` marks inferred contributions. Closure that uses
an inferred compensation is not an independent conservation check.

`reaction_invariant` describes whether the projected reaction stoichiometry
preserves the accounting quantity. It does not say whether the current run
closes. Signed Composition coefficients, including those for ThOD or Charge,
are different from negative concentrations and should not be discarded.

### Dynamic integration and compatibility

Report the actual saved `balance.integration_method`, `balance.sample_count`,
and interval. `sampled_cubic_spline` denotes cubic-spline integration with
not-a-knot boundary conditions; small sample sets can use lower-order cases.
Older snapshots may use `sampled_trapezoidal` or `sampled_previous`. A read does
not replace an older method with the current default. Missing metadata remains
unknown.

The saved report's `balance.resolution_rate` is already a percentage:
`100` means `100%`. In contrast, the calculation command's `--resolution-rate`
takes a ratio, where `1` means `100%`. Saved output points are not every internal
solver step. Higher resolution usually provides more saved points for
post-processing integration; solver tolerance controls the numerical solution.
Cubic-spline integration does not guarantee closure.

For a dynamic item outside tolerance, describe it as **“Cumulative balance
accounting difference exceeds tolerance”** and report the absolute difference,
relative difference, integration method, and sample count. Explain: **“This
difference may come from post-processing integration, numerical solution, or
missing accounting terms; it alone does not establish a simulation error.”**
Use concentration details to identify actual negative or non-finite values;
older snapshots may lack the evidence needed to locate them.

If the CLI rejects the new options, inspect `simpo get-calculation-result --help`
and the installed version. A backend that does not confirm the requested view
and filters also requires an update; the CLI does not silently present raw
results as a filtered Balance view. Updating software does not retroactively
generate missing saved snapshots. The CLI returns numeric JSON views; it does
not export Balance Sankey images.
