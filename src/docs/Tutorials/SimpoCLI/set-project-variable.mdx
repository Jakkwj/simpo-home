# `set-project-variable`: update a Variable field

Update one field in a version `0` Draft Project. The default field is `Value`,
so existing commands that set a numeric value remain valid.

## Requirements and validation

- Token scope: `write`
- The Project must belong to the Token user.
- Only Project version `0` can be modified.
- `VALUE` is required. Its syntax depends on `--field`:
  - numeric fields use a finite JSON number, such as `95.8`;
  - `Evaluation` uses `true` or `false`;
  - other writable string fields use plain text.
- `Variable` and `Tank` are read-only identifiers. They are accepted as the
  positional name and `--tank` selector, but cannot be passed to `--field`.
  Change them through the source BioModel/DataSet structure instead.
- The standard writable fields are `Value`, `Evaluation`, `InitialValue`,
  `DecimalPoint`, `LowerBound`, and `UpperBound`. The backend also accepts
  future JSON scalar columns without requiring a CLI update, except for the
  two read-only identifiers above.
- Updating `Value`, `InitialValue`, or either bound validates the complete row
  and keeps `LowerBound <= Value/InitialValue <= UpperBound`.
- Use `--tank` to identify a tank-specific row; omit it for a global Variable.

## Syntax

```text
simpo set-project-variable PROJECT_ID VARIABLE VALUE [--tank TANK] [--field FIELD] [OPTIONS]
```

Examples:

```text
simpo set-project-variable 706 S_O2 95.8 --tank AnoxicTank
simpo set-project-variable 706 S_O2 0.1 --tank AnoxicTank --field LowerBound
simpo set-project-variable 706 S_O2 false --tank AnoxicTank --field Evaluation
simpo set-project-variable 706 S_O2 3 --tank AnoxicTank --field DecimalPoint
```

These commands are rejected because the row identifiers are read-only:

```text
simpo set-project-variable 706 S_O2 X --field Variable
simpo set-project-variable 706 S_O2 NewTank --field Tank
```

Variable and Tank names identify the existing row. Use
[`get-project-variables`](./project-variables) to inspect the Project first.
The field name is case-insensitive; the response returns its canonical name.

## Options

| Option | Default | Meaning |
| --- | --- | --- |
| `--tank TANK` | omitted | Tank containing a tank-specific Variable |
| `--field FIELD` | `Value` | Existing Variable column to update |
| `--timeout SECONDS` | `10.0` | Maximum time for the HTTP request |
| `--api-token TOKEN` | configured Token | Complete Token override |
| `--base-url URL` | packaged environment URL | Backend override for this request |

## Result

The successful JSON result has `success: true` and identifies the Project,
Variable, field, old value, new value, and bounds. A non-zero exit code means no
successful update was confirmed.

### Errors

Common failures include an unknown Variable, Tank, or field; an attempt to
change read-only `Variable`/`Tank`; an invalid value type; a value outside the
inclusive bounds; a Project version other than `0`; missing `write` scope; or
Project ownership failure.

Example successful response:

```json
{
  "success": true,
  "projectId": 706,
  "projectName": "Example",
  "projectVersion": 0,
  "variable": "S_O2",
  "tank": "AnoxicTank",
  "field": "Value",
  "previousValue": 90.0,
  "value": 95.8,
  "lowerBound": 0.0,
  "upperBound": 100.0
}
```
