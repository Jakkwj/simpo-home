# SIMPO Skills Overview

This page is the directory for the AI Skills available for SIMPO. It shows
what each Skill does, how to invoke it in Codex or Claude Code, where a direct
installation is placed, and where to find the detailed installation and usage
guides.

The Codex and Claude Code packages use the same Skill content; only the
installation and invocation syntax differs.

## Current Skills

plugin support is unavailable.

## Choose a Skill

- Use **SimpoCLI** when the task operates on existing SIMPO resources or runs a
  calculation. Examples include reading Project Variables, updating a Draft
  BioModel, or checking calculation status.
- Use **SIMPO BioModel** when the task starts with a paper or explicit model specification and needs a
  scientifically reviewed BioModel. It asks for review before creating the
  Private Draft through SimpoCLI.
- Use **SIMPO DataSet** when the task starts with wastewater-treatment design
  conditions, an existing process, or source literature and needs complete,
  evidence-aware, hydraulically checked DataSet tables.
- Use **SIMPO Project** when one SCI paper should produce a linked BioModel,
  DataSet, and Project. It coordinates the two extraction workflows and adds a
  calibrated figure-data step for values that appear only in plots.
- Use **Calculation result analysis** to explain saved results, compare them
  with observations, or investigate balance and reaction contributions. A
  status-only query or raw-result download can use SimpoCLI directly.
- Combine the specialized Skills with SimpoCLI when the resulting BioModel or
  DataSet must later be inspected, updated, released, or used in a Project.

## Calculation result analysis {#calculation-result-analysis}

`calculation-result-analysis` is the fifth public Skill. It shares its scientific
analysis rules with SimpoAI's Web workflow; the CLI adapter reads through
SimpoCLI, while the Web adapter uses the existing `get_project_results` tool.
It covers ordinary calculation results as well as Balance analysis.

Balance reads remain part of
[`get-calculation-result`](./get-calculation-result), with
`--engine SIM --section steady_state_balance` or `dynamic_balance`. Available
views are `summary`, `diagnostics`, `terms`, `tanks`, `reactions`, and
`concentrations`. The Skill starts with relevant summaries or diagnostics, then
reads the requested Composition, Component, or Target details with pagination.
The `tanks` view summarizes reaction contributions by tank; it is not a complete
mass balance for each tank.

For example, invoke the installed Skill with a real Project ID:

```text
$calculation-result-analysis Explain the saved dynamic balance for Project 514.
Start with the diagnostics, then inspect the reaction contributions of any item
that needs attention. Keep the saved units and distinguish missing data from zero.
```

In the Claude Code plugin, replace the invocation with
`/simpo:calculation-result-analysis`; a personal-directory installation uses
`/calculation-result-analysis`.

This is a **read-only analysis** workflow: it does not change parameters, rerun
the solver, reintegrate saved results, or infer the final fate of a particular
influent source. A missing Balance result is unavailable, not a zero balance.
Dynamic differences are reported with their absolute and relative values,
saved integration method, and sample count. Such a difference may come from
post-processing integration, numerical solving, or missing accounting terms;
it does not by itself establish a simulation error.

The CLI Balance options require **SimpoCLI 0.1.10 or later** and a compatible
backend. The result-analysis Skill is included in the **1.1.0 package source**;
repository exports do not by themselves publish that version. Check the
published package contents before installing; older four-Skill packages do not
contain this workflow.

## Python and Poppler requirements

The ordinary `simpo` CLI commands do **not** require a user-installed Python
environment or Poppler. The requirements below apply only when the DataSet or
Project paper workflow must render PDF pages or normalize a digitizer export:

| Workflow | Required local tools |
| --- | --- |
| Design inputs, text/tables, supplied images, or supplied digitizer CSV/JSON | None for these helpers |
| Bundled figure helpers | Python 3 |
| Rendering PDF pages with `prepare_paper_figures.py` | Python 3 and Poppler `pdftoppm` |
| Automatic PDF page-count lookup | `pdfinfo` is optional when a page range is supplied |

Before rendering, the Skill checks:

```bash
python3 --version
pdftoppm -v
```

If a required tool is missing, the figure-dependent step pauses and the Skill
explains how to install it or use an equivalent renderer. It does not claim
that rendering or digitization completed. SimpoCLI's `calculate` command has a
separate requirement: the matching SimpoClient installation.

## Install and update with SimpoCLI {#install-and-update-with-simpocli}

**SimpoCLI 0.1.8 or later** supports personal-directory Skills for both assistants:

```bash
simpo skills list --target codex
simpo skills install --target codex
simpo skills update --target codex --check
simpo skills update --target codex
simpo skills install --target claude
simpo skills update --target claude
```

Install selects the Skills available in the selected bundle; update selects
installed Skills and their dependencies. The new bundle contains five Skills, while older published
bundles may contain four. Add a name to select a workflow:

```bash
simpo skills install calculation-result-analysis --target codex
simpo skills install calculation-result-analysis --target claude
```

Result analysis automatically includes its `simpo` dependency. Project selects
the available bundle workflows, including the BioModel, DataSet, and SimpoCLI
dependencies. If an update selects an installed Project Skill, the installer
also includes result analysis when the selected bundle contains it. To add only
result analysis and its `simpo` dependency, use the explicit install command
above. All Skills share
a bundle version, with minimum CLI compatibility declared separately.
`--version` selects a published version;
downgrades are refused. Older CLIs must first be upgraded using a downloaded
installer; subsequent CLI upgrades use `simpo update`.

Codex respects `CODEX_HOME`; Claude respects `CLAUDE_CONFIG_DIR`. Defaults are
`~/.codex/skills` and `~/.claude/skills`. Local Claude Skills use `/simpo` and
`/simpo-create-project`, while plugins use `/simpo:simpo` and
`/simpo:simpo-create-project`. The CLI refuses local installation if a registered
SIMPO Marketplace plugin is present; use Claude's plugin manager to update that
installation. Uninstall the plugin before switching to local Skills.

Downloads are verified against SHA-256 and size. Complete directories are
replaced, removing stale files. Manual installations and modified files are
protected: `--force` backs them up before replacement and returns the backup
directory. To migrate an existing manual or Skill Installer installation:

```bash
simpo skills install --target codex --force
```

Start a new assistant session after installation or update.

## For maintainers: publish a Skills version

For a Skills release, **manually change only `version` in
`plugins/simpo/release.json`**, for example from `0.1.8-skills.1` to
`0.1.8-skills.2`. Change `cli_min_version` only when the minimum CLI compatibility
requirement changes. The release builder synchronizes the other versions:

| File | Version maintenance |
| --- | --- |
| `plugins/simpo/release.json` | Maintainer sets the Skills version and minimum compatible CLI version. |
| `.claude-plugin/marketplace.json` | Builder synchronizes the `simpo` plugin version. |
| `plugins/simpo/.claude-plugin/plugin.json` | Builder synchronizes the plugin version. |
| `plugins/simpo/releases/index.json` | Builder records the Skills version, compatibility requirement, download URL, size and SHA-256. |

After finishing Skill source changes, run from the **SimpoHome repository root**:

```bash
python3 plugins/simpo/tools/build_release.py
```

The builder updates the other three JSON files and generates the new ZIP, such
as `plugins/simpo/releases/SIMPOSkills_0.1.8-skills.2.zip`. Commit the modified
Skills source, all four JSON files and the new ZIP together, then push to GitHub
`master` so clients can discover the release. Keep previous ZIPs and catalog
entries. Published releases are immutable; changed content requires a new
revision. Skills-only releases need no CLI rebuild or `--cli-version` argument.

## Repository and Marketplace alternatives

### Codex

Ask Codex's built-in Skill Installer to install the required repository path:

```text
Use $skill-installer to install this Skill from:
https://github.com/Jakkwj/simpo-home/tree/master/plugins/simpo/skills/simpo
```

For the BioModel Skill, replace the final path with
`plugins/simpo/skills/simpo-create-biomodel`; for the DataSet Skill, use
`plugins/simpo/skills/simpo-create-dataset`; for the paper workflow, use
`plugins/simpo/skills/simpo-create-project`. For result analysis, use
`plugins/simpo/skills/calculation-result-analysis` and also install `simpo`.
Manual installation copies the
complete directory, including `SKILL.md` and `references/`, to the matching
`$CODEX_HOME/skills/<skill-name>` directory. Include `scripts/` when present.
The Project workflow reuses the BioModel and DataSet workflows and the SimpoCLI
command reference; install those dependencies with it. Restart Codex after installation.

### Claude Code

The recommended installation installs the single `simpo` plugin, which contains
all current Skills:

```text
/plugin marketplace add Jakkwj/simpo-home
/plugin install simpo@simpo
```

After a reload, use the namespaced commands shown in the table. If the Claude
Code version cannot install plugins, copy each complete Skill directory to its
matching `~/.claude/skills/<skill-name>` fallback path.
