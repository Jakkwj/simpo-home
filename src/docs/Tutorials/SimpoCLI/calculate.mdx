# `calculate`: prepare and start a calculation

The command asks the OpenAPI to validate the Project and compile the calculation
files. By default it then passes the returned launch protocol to the locally
installed `SimpoClient` and exits without waiting for the calculation to finish.

## Requirements

- Token scope: `calculate`
- A Project owned by the Token user
- Project version `0` (Draft)
- A compatible `SimpoClient` installed on the same computer, unless
  `--no-launch` is used

## Syntax and examples

```text
simpo calculate PROJECT_ID [OPTIONS]
```

Start a Simulation and return after SimpoClient is launched:

```text
simpo calculate 706 --engine SIM
```

Start OAT sensitivity analysis and wait for a terminal status:

```text
simpo calculate 706 --engine OAT_AR --wait --wait-timeout 86400
```

Start SCE-UA with a reproducible scrambled Sobol initial population:

```text
simpo calculate 706 --engine SCEUA \
  --initialization-method scrambled_sobol \
  --fixed-initialization-seed --initialization-seed 7 --wait
```

Only prepare the files without launching SimpoClient:

```text
simpo calculate 706 --no-launch
```

## Calculation engines

`--engine` is case-sensitive and defaults to `SIM`.

| Code | Analysis |
| --- | --- |
| `SIM` | Simulation |
| `OAT_AA` | Sensitivity: absolute output / absolute input |
| `OAT_RA` | Sensitivity: relative output / absolute input |
| `OAT_AR` | Sensitivity: absolute output / relative input; recommended OAT variant |
| `OAT_RR` | Sensitivity: relative output / relative input |
| `LHS` | Uncertainty analysis using Latin Hypercube Sampling |
| `UNC` | Canonical uncertainty-analysis engine alias; uses the same uncertainty workflow as legacy `LHS` |
| `GA` | Parameter estimation with Genetic Algorithm |
| `RFGA` | Parameter estimation with the RFGA engine |
| `SCEUA` | Parameter estimation with Shuffled Complex Evolution (SCE-UA) |

The generic `OAT` code is not a public CLI choice.

## Common calculation options

| Option | Default | Accepted value |
| --- | --- | --- |
| `--threads INTEGER` | logical CPU count | `1` to the machine's logical CPU count |
| `--resolution-rate FLOAT` | `1.0` | `0.05` to `10.0`, corresponding to Dashboard `5%` to `1000%` |
| `--ode-solver TEXT` | `Forward_Euler` | only `Forward_Euler` |
| `--step-tolerance FLOAT` | `0.05` | `0.0001` to `0.2` |
| `--auto-plot / --no-auto-plot` | disabled | Enable or disable real-time local plotting |
| `--force-recalculate / --no-force-recalculate` | disabled | Force a new calculation instead of allowing result reuse |
| `--steady-state / --no-steady-state` | disabled | Enable or disable steady-state calculation |
| `--platform TEXT` | package platform | `linux`, `windows`, or `mac`; normally omit |

## Analysis-specific options

| Option | Default | Meaning |
| --- | --- | --- |
| `--intensity-oat FLOAT` | `0.01` | OAT perturbation ratio from `0.01` to `0.1` (`1%` to `10%`) |
| `--amount-lhs INTEGER` | `10` | LHS sample count, at least `2` |
| `--amount-ga INTEGER` | `1` | Number of GA/RFGA runs, at least `1` |
| `--individual-ga INTEGER` | logical CPU count | Population size, at least `1`; a multiple of `--threads` is recommended |
| `--generation-ga INTEGER` | `200` | Maximum generations, at least `1` |
| `--escaped-threshold-ga INTEGER` | `100` | Generations without improvement before early stop, at least `1` |
| `--ga-initial-value / --no-ga-initial-value` | disabled | Use current Variable values as GA/RFGA initial values |
| `--auto-plot-correlation / --no-auto-plot-correlation` | disabled | Generate OAT Pearson correlation data and plots; also requires `--auto-plot` and at least two `Evaluation=true` parameters |
| `--auto-plot-skeleton / --no-auto-plot-skeleton` | enabled | Automatic skeleton plots |

### Shared initialization options

These options are used by the algorithms that generate an initial population
or sample set:

| Option | Default | Meaning |
| --- | --- | --- |
| `--initialization-method TEXT` | `LHS` | Shared by `UNC`/`LHS`/`GA`/`RFGA`/`SCEUA`: `LHS`, `scrambled_sobol`, `sobol`, or `uniform`. |
| `--fixed-initialization-seed / --random-initialization-seed` | random | Use a reproducible seed for LHS, scrambled Sobol, or uniform. Unscrambled Sobol is deterministic and ignores the seed. |
| `--initialization-seed INTEGER` | `1` | Positive integer from `1` to `4294967295`, used when fixed seeding is enabled. |
| `--inject-initial-value / --no-inject-initial-value` | legacy GA value | For GA/RFGA/SCEUA, inject `Solution.Variable.InitialValue` into the initial population. |

### SCE-UA options

`SCEUA` evolves several Complexes and performs outer Shuffle cycles. Complexes
share the common `--threads` setting and can be evaluated in parallel.

| Option | Default | Meaning |
| --- | --- | --- |
| `--sceua-num-complexes INTEGER` | automatic | Number of independent Complexes. When omitted, uses `min(max(2, --threads), 8)`. |
| `--sceua-complex-population-size INTEGER` | omitted | Points per Complex; the backend defaults to `2 × dimension + 1`, minimum `dimension + 1`. |
| `--sceua-population-size INTEGER` | omitted | Legacy total population option. Do not combine it with the per-Complex option unless the values agree. |
| `--sceua-subcomplex-size INTEGER` | automatic | Points selected from each Complex for one temporary Sub-complex evolution step; defaults to `dimension + 1` and cannot exceed points per Complex. |
| `--sceua-evolution-steps INTEGER` | automatic | Sequential Sub-complex evolution steps for each Complex in one Shuffle; defaults to points per Complex and must be at least `1`. |
| `--sceua-max-evaluations INTEGER` | omitted | Total objective evaluations, including initialization; the backend defaults to `20 × total population` and requires at least total population. |
| `--sceua-max-shuffles INTEGER` | `0` | Optional hard limit on outer Shuffle cycles; `0` disables this limit. |
| `--sceua-convergence-shuffles INTEGER` | `10` | Consecutive insufficient-improvement Shuffles before early stopping. |
| `--sceua-objective-tolerance FLOAT` | `1e-4` | Relative objective improvement threshold; positive values require convergence shuffles. |
| `--sceua-parameter-tolerance FLOAT` | `1e-4` | Normalized parameter-spread threshold; `0` disables it. |

The total SCE-UA population is `--sceua-num-complexes ×
--sceua-complex-population-size`. The objective and parameter early-stop
branches use an **OR** relationship: SCE-UA stops when either criterion is met.
`Maximum Shuffles` is an optional outer-cycle cap; leave it at `0` when the
evaluation budget and convergence criteria should determine termination.

During each Shuffle, every Complex performs `Evolution Steps` sequential local
evolution steps. Each step selects `Sub-complex Size` points from that Complex,
updates the trial point, and writes the accepted result back before the next
step selects a new Sub-complex. These two options correspond to the algorithm's
internal NPS and NSPL controls.

## Launch and wait options

| Option | Default | Meaning |
| --- | --- | --- |
| `--no-launch` | disabled | Prepare files but do not start local SimpoClient |
| `--print-protocol` | disabled | Include the secret, short-lived launch protocol in JSON |
| `--client-main PATH` | installed SimpoClient | Optional override for a custom SimpoClient executable or `main.py` |
| `--wait / --no-wait` | disabled | Poll until `completed`, `failed`, `stopped`, or `idle` |
| `--poll-interval SECONDS` | `2.0` | Delay between status requests while waiting |
| `--wait-timeout SECONDS` | `86400` | Maximum time this CLI polls; does not stop the calculation |
| `--timeout SECONDS` | `3700` | Timeout for the single backend preparation/compilation request |
| `--async-preparation / --no-async-preparation` | disabled | Queue preparation as a durable backend Operation |
| `--wait-preparation / --no-wait-preparation` | disabled | Wait for async preparation before launching SimpoClient |
| `--preparation-wait-timeout SECONDS` | `86400` | Maximum wait for preparation Operation |
| `--preparation-poll-interval SECONDS` | `2.0` | Delay between preparation status requests |
| `--idempotency-key TEXT` | omitted | Stable retry key for asynchronous preparation |
| `--api-token TOKEN` | configured Token | Complete Token override |
| `--base-url URL` | packaged environment URL | Backend override for this request |

`--no-launch` cannot be combined with `--wait`. If `--wait-timeout` expires,
only the waiting CLI exits; SimpoClient and the calculation continue. Check them
later with [`get-calculation-status`](./get-calculation-status), or explicitly use
[`stop-calculation`](./stop-calculation).

For long preparation requests, use `--async-preparation --no-launch`, retain the
returned `operationId`, and run `wait-operation`. If the CLI should start the
local client after preparation, use `--async-preparation --wait-preparation`.

`--print-protocol` is intended for explicit integrations. The protocol contains
a short-lived credential and must not be published or written to public logs.

OAT sensitivity ranking and weighted-integral results do not mean that parameter
correlations were calculated. Correlation output is disabled by default. To
request Pearson coefficients or the Dashboard Correlation panel, enable both
switches:

```text
simpo calculate PROJECT_ID --engine OAT_AR \
  --auto-plot --auto-plot-correlation --wait
```

Enabling `--auto-plot-correlation` alone may still return an empty
`correlation` object because the client generates correlation data only when
automatic plotting is also enabled. At least two parameters must have
`Evaluation=true`; with fewer than two there is no pairwise coefficient, so an
empty result is expected and must not be reported as zero correlation.

## Initial DataSet values

For a calculation, `Solution.Variable.Value` is the baseline for `Inflow` and
`Flow`. The backend compares it with the DataSet value at `time=0`, adds the
resulting offset to every row, and clips negative values. `Inflow` resolves its
selected `Conversion` expression using the current BioModel/Project Parameter
values first:

```text
Inflow offset = Variable.Value * Conversion coefficient - DataSet first value
Flow offset   = Variable.Value - DataSet first value
```

For example, a one-to-one Inflow series beginning at `100` with a Solution value
of `1000` is shifted by `900`, so `[100, 120, 90]` is calculated as
`[1000, 1020, 990]`. Flow is converted from `m3/d` to `m3/s` after the shift.

This rule does not apply to `Measured`: its values remain the original
observations used for comparison with model output. When documenting a run,
record the DataSet first value, Solution value, original Conversion expression,
resolved coefficient, and effective offset instead of pre-shifting the stored
DataSet.

## Result

Without `--wait`, success confirms preparation and local launch, not completion:

With `--wait`, `finalStatus` contains the terminal backend status.

```json
{
  "success": true,
  "projectId": 706,
  "projectName": "Example",
  "projectVersion": 0,
  "engine": "SIM",
  "clientPid": 12345,
  "launched": true,
  "launchBeforeSeconds": 3600,
  "finalStatus": null
}
```
