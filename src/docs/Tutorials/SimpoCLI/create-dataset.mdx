# `create-dataset`: create a Draft DataSet

Create an owned, Private, version `0` Draft DataSet. Without `--json`, the
backend creates and parses the standard blank DataSet. With `--json`, it parses
the supplied complete DataSet detail during the same create operation.

## Requirements

- Token scope: `write`
- The name must be 1 to 230 characters and unique among the account's Draft DataSets.
- JSON must contain `Unit`, `Target`, `Tank`, `Pump`, `Measured`, `Inflow`,
  `Flow`, and `Connection` arrays.
- `Unit`, `Target`, `Tank`, and `Connection` must contain their header rows.
  The other four tables may be empty arrays.
- `Environment` is optional; omit it or use `[]` when there are no temperature samples.

## Syntax

```text
simpo create-dataset NAME [--json DETAIL.json] [OPTIONS]
```

Examples:

```text
simpo create-dataset InfluentData
simpo create-dataset InfluentData --json ./DataSet.json
```

## Options

| Option | Default | Meaning |
| --- | --- | --- |
| `--json FILE` | standard blank DataSet | UTF-8 complete DataSet `detail` object |
| `--description TEXT` | empty | Optional description |
| `--sourcepaper-id ID` | no source paper | Optional source paper database ID |
| `--timeout SECONDS` | `3700.0` | Maximum parsing and HTTP time |
| `--api-token TOKEN` | configured Token | Complete Token override |
| `--base-url URL` | packaged environment URL | Backend override for this request |

## Water-temperature input {#temperature-input}

Use `Environment` for Tank water-temperature time series. The JSON table has the
same two header rows as the [Environment XLSX sheet](../DataSet/Edit.mdx#environment):
Tank names in the first row, `T` in the second, then time/value rows. For example:

```json
{
  "Environment": [
    {"0": "Tank", "1": "Tank1", "2": "Tank", "3": "Tank2"},
    {"0": "Environment", "1": "T", "2": "Environment", "3": "T"},
    {"0": 0, "1": 20, "2": 0, "3": 18},
    {"0": 1, "1": 25, "2": 0.5, "3": 19}
  ]
}
```

This is a fragment: merge it into the complete DataSet `detail` object, preserving
the eight required tables. `Tank1` and `Tank2` must exist in `Tank`. Time uses
`Unit.Time`; each series starts at time `0`, with strictly increasing, finite,
non-negative times and finite temperatures from **0 to 40°C**. One sample at `0`
defines a constant temperature. Each `(Tank, Environment)` pair must be unique.
Use `Clarifier_Outlet` and `Clarifier_Blanket` for point-settler zones. A zone uses
its own series first, then its parent Tank's series; with neither, it uses **20°C**.
Only the sheet name `Environment` and the temperature identifier `T` are supported.

Include the fixed temperature unit as the sixth `Unit` column:

```json
{
  "Unit": [
    {"0": "Time", "1": "Volume", "2": "Flow", "3": "Area", "4": "Height", "5": "T"},
    {"0": "day", "1": "m3", "2": "m3/d", "3": "m2", "4": "m", "5": "℃"}
  ]
}
```

An omitted `Unit.T` defaults to Celsius. For Pump aeration, the sixth Pump column
is the oxygen-transfer temperature factor `θ`:

```json
{
  "Pump": [
    {"0": "Name", "1": "Type", "2": "SOTEa", "3": "SOTEb", "4": "SOTEc", "5": "θ"},
    {"0": "Pump1", "1": "Air", "2": 0.3259, "3": 0.3142, "4": 0.2567, "5": 1.024}
  ]
}
```

Use coefficients appropriate to your Pump; the values above only illustrate the
format. New Pumps in the Dashboard start at `1.024`; a missing or blank `θ`
uses `1`, preserving the uncorrected transfer coefficient. This does not disable temperature correction of saturated dissolved
oxygen, and direct Tank `KLa` does not use Pump `θ`. See the
[DataSet temperature equations](../DataSet/Edit.mdx#do-temperature) and
[`calculate` input handling](./calculate#temperature-input).
