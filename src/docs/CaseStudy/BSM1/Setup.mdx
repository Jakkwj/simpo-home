# Configure and run BSM1

In this exercise you will run a 14-day simulation twice. First supply a fixed oxygen-transfer coefficient and let the oxygen concentration in Tank5 respond to the incoming wastewater. Then let a controller adjust aeration as it tries to hold the oxygen concentration at 2 g O₂/m³. Keep the <a href={projectLinks['03'] + '?result=simulation&tank=Tank5&target=S_O2'}>saved open-loop Tank5 oxygen chart</a> and the <a href={projectLinks['04'] + '?result=simulation&tank=Tank5&target=S_O2'}>saved closed-loop Tank5 oxygen chart</a> available for comparison.

## Make a working copy of the plant {#create}

1. Sign in to SimpoDash and open <a href={projectLinks['03'] + '?view=detail'}>03 · Dry, open loop</a>. Copy the **Project** using **Clone** in the Detail toolbar. Give it a name you have not used for a Project, BioModel or DataSet, such as `BSM1_Dry_Open_Practice`. The clone includes the linked BioModel, DataSet and Solution.
2. Open your copy in **Personal Projects**. Check the **Draft** label beside its name. The public version remains available in its own tab as the reference for this exercise.
3. Open **Detail**. The three views below answer different questions about the same simulation. For the first run, work with the values already saved in the copy.

| View in Detail | Question it answers | What to find in case 03 |
| --- | --- | --- |
| **BioModel** | What reactions can happen in the water? | ASM1 defines components such as dissolved oxygen, `S_O2`, and reactions that consume oxygen. |
| **DataSet** | Where do those reactions happen, and what enters the plant? | Five biological reactors, a ten-layer settler, an influent and two aeration pumps. The DataSet also holds the MATLAB time series used for comparison. |
| **Solution** | Where does the simulation start, and how are its outputs compared? | **Variable** holds initial values, **Conversion** maps model components to the DataSet targets, and **Weight** sets the comparison weights. The plants start with water and sludge already in the tanks. |

If you edit a project input, use **Parse** in Detail to validate it and save the Draft before calculating. [Cloning a public Project](../../Tutorials/Project/Create.mdx)

## Exercise 1 · Reproduce the dry open loop {#first-run}

Above Tank5 the separate `KLaPump5` connection supplies `KLa_5 = 84` d⁻¹. Open **List → Controllers**. An empty list is expected in case 03. The influent keeps changing while this aeration coefficient stays fixed.
3. **Set up the run.** In your Draft, open **Calculation → Console**, choose the **Simulation** task and select **General**. Use the settings below for this first reproduction. The console uses Forward Euler for these cases.

   | Group | Field | Value for the exercise |

   | Solver & Performance | Step Tolerance (%) | 5 |

   The first run on this computer normally works with **Run & Output → Recalculate** switched off. SimpoClient runs the solver if it has no matching local result or if inputs or settings have changed. Switch it on when you want to repeat an identical run from scratch.

4. **Start and check the time axis.** Click **Start** and follow the prompt to open SimpoClient if one appears. Once the run finishes, open **Calculation → Simulation**. The dynamic run spans **0–336 h**, with one result every **0.25 h (15 minutes)**. That gives 1,345 times including the starting point. These times are already supplied by the cloned case.

## Exercise 2 · Close the two feedback loops {#closed-loop}

Read the three tabs in order. **Sensor** measures `Tank5.S_O2`. **PI Controller** compares that reading with **2 g O₂/m³**. **Control Handle** sends the resulting command to `KLa_5`, within **0–360 d⁻¹**. Follow `BSM1_Qintr` in the same way, from nitrate in Tank2 to the internal recycle `Q_a`. The lines are visible on the flowsheet when **Tools → Signals** is on.

**Try replacing the closed-loop inputs.** In a copy of case 04, keep the two Flow names, connections and timestamps, the controller settings and initial states. Replace the zero entries with the open-loop values of **55,338 m³/d** and **84 d⁻¹**, respectively. Across the same 14 days, water quality, applied handle values and all seven Assessment metrics match the run with zeros. To configure the loops, one row at time zero with a value of zero suffices for each handle. Clearing the first value of either series fails DataSet validation.

## Inspect the settler and the oxygen supply {#aeration}

`Tank1` and `Tank2` are 1,000 m³ anoxic reactors. `Tank3`–`Tank5` are 1,333 m³ aerated reactors. All five have constant volume. Open `Tank6` on the flowsheet. Its **Takacs Settling** configuration has 10 layers, a surface area of 1,500 m², a height of 4 m and feed layer **6**. SIMPO numbers layers from the bottom up. Effluent leaves the top layer `Tank6_10`. Return sludge `Q_r` and waste sludge `Q_w` leave the bottom layer `Tank6_1`. The internal recycle `Q_a` returns from `Tank5` to `Tank1`.

Check the geometry against the volumes in the Project. Tank6 holds $1{,}500 \times 4 = 6{,}000$ m³. Each of its ten layers is 0.4 m deep and holds 600 m³. In the Tank6 detail, select **Measured** and change the layer to 10 to inspect the reference for the effluent. Select layer 1 to inspect the bottom sludge. The conical flowsheet icon shows the layer order. The model uses the same area for every layer.

**Keep ten layers and feed layer 6 when reproducing BSM1.** When creating a settler for another plant, SIMPO accepts 3–10 layers. The feed needs at least one layer above it and one below it. A ten-layer settler can feed layers 2–9, while a three-layer settler feeds layer 2. Dividing the total depth by the number of layers gives the 0.4 m layer depth in this case.

**Keep the layers in place during a storm and let the solver adjust its internal step.** Faster flow or thinner layers can carry a change in water or solids into an adjacent layer sooner. The Forward Euler solver calculates an upper time-step limit for each layer from the water flow and settling flux, then takes the smallest of those limits. Many internal steps can fit between successive 15-minute output records. [Time-step constraint and worked example](../../Tutorials/DataSet/Edit.mdx#takacs-step)

**KLaPump takes a volumetric oxygen-transfer coefficient in d⁻¹.** On the DataSet flowsheet, follow the two lines from `KLaPump34` and the line from `KLaPump5`. Open the named Flow on each line to inspect its time series. All eight cases use these three connections.

| From | Flow | Into | Open-loop input |
| --- | --- | --- | ---: |
| `KLaPump34` | `KLa_34` | `Tank3` | 240 d⁻¹ |
| `KLaPump34` | `KLa_34` | `Tank4` | 240 d⁻¹ |
| `KLaPump5` | `KLa_5` | `Tank5` | 84 d⁻¹ |

Each reactor connected to `KLa_34` receives the full 240 d⁻¹. KLa inputs share the time-and-value column layout of water flows in `Flow`. The coefficient enters the oxygen-transfer calculation. Only water streams enter the hydraulic balance. Times use `Unit.Time = hour`. All cases fix `Q_r = 18446` and `Q_w = 385 m³/d`. Open loop also fixes `Q_a = 55338 m³/d`. In closed loop, the two controllers supply the effective values of `Q_a` and `KLa_5`.

In the pump details both pumps use `θ = 1` and `TRef = 20` °C. In a general project, the reference coefficient is multiplied by $\theta^{T-T_{ref}}$ at each receiving tank's temperature. Setting θ to 1 makes the coefficient temperature-independent in these cases. **The BSM1 dissolved oxygen saturation concentration is set on the receiving reactor** by opening the CSTR details for Tank3, Tank4 or Tank5. Choose **Oxygen Saturation Model → Constant** and enter **8 mg O₂/L** as the **Saturation Value**. In the workbook these are `CSTRTank.SaturationModel = Constant` and `SaturationValue = 8`. To check the fixed d⁻¹ unit for KLa, open **List → Unit** on the flowsheet. For example, if `Tank5` in open loop has 2 g O₂/m³ of DO, the instantaneous transfer rate is $84(8-2)=504$ g O₂/(m³·d). An Assessment formula can read the named input `KLa_5` or use `Tank5.KLa` for the effective combined coefficient at the tank, as in the aeration energy calculation. [Compare saturation settings for typical plants, BSM2 and BSM1](../../Tutorials/DataSet/Edit.mdx#do-temperature)

## Mixed inlet response at Tank1 {#mixed-inlet}

`Tank1` receives the external influent `Q_0`, internal recycle `Q_a` and return sludge `Q_r`. The BSM1 MATLAB/Simulink implementation used here applies a first-order lag to the combined inlet ahead of the first reactor. In all eight cases open **Tank1 → CSTR details → Mixed Inlet Response** and check that **First-order lag** has a **Time Constant** of **8.64 seconds**. `Tank2`–`Tank5` use instantaneous mixing. This feature uses constant-volume hydraulics and the Forward Euler solver. For a simple example, suppose combined inlet flow jumps from 90,000 to 100,000 m³/d and stays there. After 8.64 seconds the flow reaching the reactor is about 96,320 m³/d. It has already begun to change and continues towards 100,000. Linear interpolation specifies the input between two recorded samples. The lag governs how Tank1 responds to that input.

The filter acts on **total liquid flow** and **each component's mass load**. The equations below sum the incoming streams and update the two filtered quantities for component $j$.

$$
Q_{in}=\sum_i Q_i,\qquad L_{j,in}=\sum_i Q_i C_{j,i},\qquad
\tau\frac{dQ_f}{dt}=Q_{in}-Q_f,\qquad
\tau\frac{dL_{j,f}}{dt}=L_{j,in}-L_{j,f}.
$$

Use consistent time units for $t$ and $\tau$. The reactor receives filtered flow $Q_f$ and component load $L_{j,f}$. Following a sustained step in the incoming total flow, the filtered flow completes about 63% of the change in one time constant. The outlet of `Tank1` and downstream branches carrying the remaining flow respond accordingly. Use `Branch("Tank6_10", "Outflow")` when the actual effluent flow is needed for a dynamic effluent-load calculation.

When reproducing a public case, keep Tank1’s startup settings. For a new CSTR, SIMPO initializes the inlet automatically from the feed and recycles at the start of the simulation.

## How the two controllers work {#controller}

Each controller reads one simulated water-quality target at a particular location. Its sensor supplies a reading, the PI compares that reading with the setpoint, and its actuator adjusts one independent handle. A line labelled `Q_0+Q_r` carries a calculated flow. Bind the controller to a single named handle such as `Q_a`. To reproduce the reference, retain the supplied bindings and initialization. To draw the same connections in a new diagram, select **New Controller**, drag the measurement location to the controller and drag its output to the desired flow or KLa connection. Open the controller and complete **Sensor**, **PI Controller** and **Control Handle**, then apply and save.

| Field in `Controller` | Nitrate and internal recycle | Dissolved oxygen and aeration |
| --- | --- | --- |
| `Name` | `BSM1_Qintr` | `BSM1_KLa5` |
| `SensorPreset` | `BSM_Class_B0` | `BSM_Class_A` |
| `SensorLocation`, `SensorTarget` | `Tank2`, `S_NO` | `Tank5`, `S_O2` |
| `SensorLowerLimit`, `SensorUpperLimit` | 0–20 g N/m³ | 0–10 g O₂/m³ |
| `ControllerSetpoint` | 1 g N/m³ | 2 g O₂/m³ |
| `ControllerGain` | 10,000 (m³/d)/(g N/m³) | 25 (d⁻¹)/(g O₂/m³) |
| `ControllerIntegralTime`, `ControllerTrackingTime` | 0.025 d, 0.015 d | 0.002 d, 0.001 d |
| `ControlHandle` | `Q_a` | `KLa_5` |
| `HandleLowerLimit`, `HandleUpperLimit` | 0–92,230 m³/d | 0–360 d⁻¹ |

For example, a DO reading of 1.8 at a setpoint of 2 gives an error of $2-1.8=0.2$ g O₂/m³. The proportional contribution is $25\times0.2=5$ d⁻¹. The PI adds the bias, integral state and anti-windup correction. Command limits and the actuator response then determine the actual `KLa_5`. Integral time sets how quickly a persistent error accumulates. Tracking time sets how quickly the anti-windup correction follows the limited command when an output limit is reached. Enter both in **days**, including when the DataSet time unit is hours. Use the supplied gains and times for reproduction. Controller trial is available for exploring other tunings. [Sensor, PI and trial documentation](../../Tutorials/DataSet/Edit.mdx#controller)

Look at the actual signals at hour 168 in case 04. The simulated tank DO was **1.962 g O₂/m³**, while the sensor read **2.215 g O₂/m³** after its response and noise were applied. The PI acted on the sensor reading, so its error was about $2-2.215=-0.215$ g O₂/m³. Its aeration command was **154.51 d⁻¹**. The actuator was still responding and delivered **161.77 d⁻¹**. In the water-quality chart, **Measured** labels the MATLAB comparison series. The sensor reading belongs to the feedback loop inside this simulation.

**Case 02 and cases 04/06/08 differ in their instrumentation and initialization.** The 500-day closed-loop startup in case 02 uses ideal noise-free sensors, a first-order internal-recycle actuator and direct application of the tank 5 aeration command. The feedback in cases 04, 06 and 08 follows the sensor and actuator dynamics.

- The continuous Class B0 nitrate sensor has a 10-minute 90% response time and noise standard deviation of 0.50 g N/m³. The corresponding values for the continuous Class A DO sensor are 1 minute and 0.25 g O₂/m³.
- Both sensors update at internal integration steps. The BSM1 noise source provides values every minute from day 0 through day 14, with DO on channel 1 and nitrate on channel 2. The DataSet’s 15-minute `Measured` series contains the MATLAB comparison trajectory. The simulated plant provides the live feedback.
- In the closed-loop Projects, open either controller and expand **Fixed Settings** on the Sensor and PI Controller tabs and **Fixed Actuator Settings** on the Control Handle tab. The visible presets and gains in cases 02 and 04 match, but the Projects preserve different instrument dynamics and initial states. The sensor reading drives the PI, the limits bound its command, and the actuator determines the input that reaches the plant.

### Which inputs may a BSM1 control strategy change? {#control-handles}

A *control handle* is the quantity the strategy can change. In the default nitrate loop, for example, the sensor measures nitrate in Tank2, the PI aims for 1 g N/m³, and its handle is the **internal recycle flow** `Q_a`. Independent reactor aeration needs its own KLa signal (the supplied cases share `KLa_34` between Tank3 and Tank4). Carbon dosing needs an Inflow with the specified substrate concentration and a named dosing Flow. For a split, configure branch flows that add up to the parent flow; entering 0 and 1 as limits on a single Controller does not enforce that sum. #### How SIMC estimates PI settings from a step test

A step test runs when you request an estimate. SimpoClient holds the external inputs at their initial values, turns off sensor noise and holds the selected handle at its operating point while the plant settles. Two runs then start from that same state. One holds aeration constant and the other applies a small step. SIMPO fits a first-order model with a time delay to the **difference between the two sensor readings**. The fit gives the process gain $k$ (the steady change in DO divided by the aeration step), the time constant $\tau$ and the delay $\theta$. This warm-up is independent of the 6, 24 or 72 h trial window.

SIMPO calculates proportional gain $K_c$ and integral time $T_i$ using **Sigurd Skogestad’s SIMC tuning rules**. For a first-order process and a chosen closed-loop response time $\tau_c$, the rules are

$$
K_c=\frac{\tau}{k(\tau_c+\theta)},\qquad T_i=\min\bigl(\tau,\,4(\tau_c+\theta)\bigr).
$$

The source is Sigurd Skogestad (2003), *Simple analytic rules for model reduction and PID controller tuning*, *Journal of Process Control* 13, 291–309, Table 1, first-order process. [DOI](https://doi.org/10.1016/S0959-1524(02)00062-8) · [Author’s full text](https://skoge.folk.ntnu.no/publications/2003/tuningPID/finalpaper.pdf)

**How SIMPO applies the rule.** With $\Delta t$ equal to the sampling interval on the fitted curve, SIMPO selects $\tau_c=\max(\tau/2,\,\theta,\,2\Delta t)$. It estimates the anti-windup tracking time $T_t$ separately as $\max(T_i/2,\,\Delta t)$. All times here are in days. SIMPO then restores the original project state, dynamic influent and configured sensor noise to check the candidate in closed loop. If the DO response is too weak to identify, the fit is poor or the candidate materially worsens tracking, the panel explains why and retains the entered values. Check the measurement, handle and limits, or enter a complete set and compare it with **Run trial**.

## Match the simulation clock to the comparison window {#run}

| Setting | 01/02, constant-influent startup | 03–08, dynamic weather |
| --- | --- | --- |
| Execution mode | **Dynamic**, integrate 500 days from the supplied initial state and retain the approach to steady state. | **Dynamic**, initialize from the end of the corresponding open- or closed-loop 14-day dry-weather pre-run, then run 14 days of the selected weather. |
| Input interpolation | **Linear**. Constant influent has the same value between samples. | **Linear** between adjacent input samples. |
| Solver and resolution | **Forward Euler, 100%**. Save one point every 4 hours, giving 3,001 points including both endpoints. | **Forward Euler, 100%**. Save one point every 15 minutes, giving 1,345 points including both endpoints. |
| Assessment window | Days 493–500, the final week of steady operation. | Days 7–14, the second week of the dynamic benchmark. |
| Closing sludge inventory for SP | `Change(inventory, -1)` uses the sample at day 499, 20:00 (4 hours back). | The same formula uses day 13, 23:45 (15 minutes back), matching the BSM1 working group’s script. |

Here, `inventory` stands for the sum of volume times TSS over all reactors and settler layers in the SP formula. The offset counts saved samples. The initial inventory still comes from the first sample, and the waste flow is integrated over the full seven days. Enable **Recalculate** in the Console when repeating these runs from an older saved result.

**Linear is the Dynamic Input Interpolation Method in the Project console.** In case 03, for example, `Q_0` is 21,477 m³/d at hour 0 and approximately 21,474 m³/d at hour 0.25. Linear supplies about **21,475.5 m³/d** at hour 0.125. Previous would still supply 21,477. This option interpolates `Flow`, `Inflow` and any temperature inputs. Each feedback loop uses calculated process values. Since all eight trajectories use Dynamic execution, the steady-state input averaging option does not enter the calculation. [Dynamic input interpolation](../../Tutorials/Project/Calculation.mdx)

**Step tolerance and the output interval are separate settings.** In Dash's **Step Tolerance (%)** field, enter `5` to reproduce the updated 5% runs, `0.1` for 0.1%, or `0.01` for 0.01%. The corresponding solver fractions are `0.05`, `0.001` and `0.0001`. With output resolution at 100%, a tighter tolerance allows finer internal integration while retaining the same observation times for direct comparison. See the [eight-case tolerance comparison](./Results.mdx) to choose the precision for a benchmark run.

After the run, open **Calculation → Simulation**. Select a location and target to compare the **Predicted** trajectory against **Measured** at the same times. For example, select Tank5 and `S_O2` in case 04 to inspect the controlled oxygen concentration, then open **Assessment** and read the aeration energy over days 7–14. If the curves disagree from the first sample, check the starting state and input interpolation. If they diverge only during the storm peak in a few settler layers, compare integration tolerances.
