# SIMPO Skill 总览

本页是 SIMPO AI Skill 的统一目录，汇总每个 Skill 的功能、Codex 和 Claude Code
中的调用方式、安装目录，以及对应的安装和使用详情。

Codex 和 Claude Code 使用相同的 Skill 内容，区别主要在安装方式和调用语法。

## 当前 Skill

| --- | --- | --- | --- | --- | --- |
| [SimpoCLI](./simpo-cli-skill) | 操作已安装的 SimpoCLI：认证、BioModel、DataSet、Project、Variable、计算任务和分页结果。 | `$simpo` | `$CODEX_HOME/skills/simpo`<br />默认：`~/.codex/skills/simpo` | `/simpo:simpo` | 推荐：由 `simpo` 插件管理。<br />备用：`~/.claude/skills/simpo` |

不支持插件时使用的个人 Skill 目录。

## 如何选择

- **SimpoCLI**：用于操作已有的 SIMPO 资源或运行计算，例如读取 Project Variable、
  更新 Draft BioModel、查询计算状态。
- **SIMPO BioModel**：用于从论文或明确的用户模型定义开始建立模型。它负责信息提取、推导和审核，并在确认后
  通过 SimpoCLI 创建 Private Draft BioModel。
- **SIMPO DataSet**：用于从污水处理设计条件、已有工艺或来源文献开始，建立完整、保留
  证据并经过水力检查的 DataSet 表格。
- **SIMPO Project**：用于从一篇 SCI 论文同时准备关联的 BioModel、DataSet 和
  Project；图表中的数据点会经过坐标校准并保留数字化证据。
- 生成的 BioModel 或 DataSet 如需继续查询、更新、发布或用于 Project，可再使用
  **SimpoCLI** 执行日常操作。

## Python 和 Poppler 依赖

普通的 `simpo` CLI 命令**不要求**用户另外安装 Python 或 Poppler。只有在 DataSet
或 Project 的论文流程需要渲染 PDF 页面或规范化数字化导出文件时，才适用下表：

| 流程 | 本地工具要求 |
| --- | --- |
| 工程输入、文字/表格、用户提供的图片或数字化 CSV/JSON | 不需要这些辅助工具 |
| 运行图片辅助脚本 | Python 3 |
| 使用 `prepare_paper_figures.py` 渲染 PDF 页面 | Python 3 和 Poppler 的 `pdftoppm` |
| 自动读取 PDF 页数 | 提供明确页码范围时不需要 `pdfinfo` |

渲染前，Skill 会检查：

```bash
python3 --version
pdftoppm -v
```

缺少必需工具时，依赖图片的步骤会暂停，并明确提示安装方式或等效渲染工具。不会把
未完成的渲染或数字化报告为成功。SimpoCLI 的 `calculate` 命令另有单独要求：安装匹配
版本的 SimpoClient。

## 使用 SimpoCLI 安装和更新

SimpoCLI **0.1.8 起**支持管理两个助手的个人目录 Skills：

```bash
simpo skills list --target codex
simpo skills install --target codex
simpo skills update --target codex --check
simpo skills update --target codex
simpo skills install --target claude
simpo skills update --target claude
```

不指定名称时安装全部四项；更新命令选择已安装的 Skills。可以添加
`simpo-create-project` 等名称选择一个工作流，Project 会自动补齐其余三项依赖。
四项共用 `0.1.8-skills.1` 这样的版本号，仅 Skills 更新时递增后缀，最低兼容 CLI
版本单独声明。`--version` 可指定已发布版本，不支持降级。旧 CLI 需要先下载安装新版，
后续程序升级使用 `simpo update`。

Codex 遵循 `CODEX_HOME`，Claude 遵循 `CLAUDE_CONFIG_DIR`，默认目录分别是
`~/.codex/skills` 和 `~/.claude/skills`。本地 Claude Skills 使用 `/simpo`、
`/simpo-create-project` 调用；插件使用 `/simpo:simpo`、
`/simpo:simpo-create-project`。已注册 SIMPO Marketplace 插件时，CLI 会拒绝本地
安装，应继续通过 Claude 插件管理器更新。切换到本地 Skills 前请先卸载插件。

下载会校验 SHA-256 和大小，安装会替换完整目录、移除旧版遗留文件。
手工安装及本地修改默认不会被覆盖；加 `--force` 会先备份，并返回备份目录。
已有手工安装或 Skill Installer 安装时，可以这样迁移：

```bash
simpo skills install --target codex --force
```

安装或更新后请开启新的助手会话。

## 维护者：发布新版 Skills

发布 Skills 时，**只需手动修改 `plugins/simpo/release.json` 中的 `version`**。
例如从 `0.1.8-skills.1` 改为 `0.1.8-skills.2`。`cli_min_version` 仅在最低 CLI
兼容要求变化时调整。其余版本由发布脚本自动同步：

| 文件 | 版本维护方式 |
| --- | --- |
| `plugins/simpo/release.json` | 手动设置 Skills 版本和最低兼容 CLI 版本。 |
| `.claude-plugin/marketplace.json` | 脚本同步 `simpo` 插件版本。 |
| `plugins/simpo/.claude-plugin/plugin.json` | 脚本同步插件版本。 |
| `plugins/simpo/releases/index.json` | 脚本写入 Skills 版本、兼容要求、下载地址、文件大小和 SHA-256。 |

完成 Skill 源码修改后，在 **SimpoHome 根目录**执行：

```bash
python3 plugins/simpo/tools/build_release.py
```

脚本会同步另外三个 JSON，并生成新版 ZIP，例如
`plugins/simpo/releases/SIMPOSkills_0.1.8-skills.2.zip`。将修改过的 Skill 源码、
这四个 JSON 和新 ZIP 一起提交并推送到 GitHub `master`，客户端才能发现新版。
保留旧版本的 ZIP 和发布清单记录；已发布版本内容不可覆盖，内容变化时递增修订号。
仅更新 Skills 不需要重新打包 CLI，也不需要传入 `--cli-version`。

## 仓库和 Marketplace 备用方式

### Codex

让 Codex 内置的 Skill Installer 安装对应的仓库路径：

```text
Use $skill-installer to install this Skill from:
https://github.com/Jakkwj/simpo-home/tree/master/plugins/simpo/skills/simpo
```

安装 BioModel Skill 时，将最后的路径改为
`plugins/simpo/skills/simpo-create-biomodel`；安装 DataSet Skill 时改为
`plugins/simpo/skills/simpo-create-dataset`；安装 SIMPO Project Skill 时改为
`plugins/simpo/skills/simpo-create-project`。手工安装时，必须把包含 `SKILL.md` 和
`references/` 的完整目录复制到对应的 `$CODEX_HOME/skills/<skill-name>`；完成后重启
Codex 会话。有 `scripts/` 的目录也须完整保留。Project 工作流需要安装全部四项
Skill，因为它复用 BioModel、DataSet 流程和 SimpoCLI 命令参考。

### Claude Code

推荐安装包含全部四项 Skill 的 `simpo` 插件：

```text
/plugin marketplace add Jakkwj/simpo-home
/plugin install simpo@simpo
```

重新加载插件后，使用表格中的带命名空间命令。如果 Claude Code 版本不支持插件，可将
每个完整 Skill 目录复制到对应的 `~/.claude/skills/<skill-name>` 备用目录。
