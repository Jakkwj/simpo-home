# `calculate`：准备并启动计算

命令先请求 OpenAPI 校验 Project 并编译计算文件。默认随后把后端返回的启动
协议传给本机安装的 `SimpoClient`，并在客户端启动后直接退出，不等待计算
完成。

## 使用条件

- Token scope：`calculate`
- Project 属于当前 Token 用户
- Project version 为 `0`（Draft）
- 同一台电脑安装兼容版本的 `SimpoClient`，使用 `--no-launch` 时除外

## 命令格式和示例

```text
simpo calculate PROJECT_ID [OPTIONS]
```

启动 Simulation，并在 SimpoClient 启动后返回：

```text
simpo calculate 706 --engine SIM
```

启动 OAT 敏感性分析并等待终态：

```text
simpo calculate 706 --engine OAT_AR --wait --wait-timeout 86400
```

使用固定 Seed 的 Scrambled Sobol 初始总体启动 SCE-UA：

```text
simpo calculate 706 --engine SCEUA \
  --initialization-method scrambled_sobol \
  --fixed-initialization-seed --initialization-seed 7 --wait
```

只准备文件，不启动 SimpoClient：

```text
simpo calculate 706 --no-launch
```

## 计算引擎

`--engine` 区分大小写，默认值为 `SIM`。

| 代码 | 分析类型 |
| --- | --- |
| `SIM` | Simulation 仿真 |
| `OAT_AA` | 敏感性分析：绝对输出 / 绝对输入 |
| `OAT_RA` | 敏感性分析：相对输出 / 绝对输入 |
| `OAT_AR` | 敏感性分析：绝对输出 / 相对输入；推荐的 OAT 变体 |
| `OAT_RR` | 敏感性分析：相对输出 / 相对输入 |
| `LHS` | Latin Hypercube Sampling 不确定性分析 |
| `UNC` | 当前不确定性分析引擎名称；与旧版 `LHS` 使用同一套不确定性流程 |
| `GA` | Genetic Algorithm 参数估值 |
| `RFGA` | RFGA 参数估值 |
| `SCEUA` | Shuffled Complex Evolution（SCE-UA）参数估值 |

通用的 `OAT` 不是 CLI 的公开选项。

## 常用计算参数

| 选项 | 默认值 | 可接受值 |
| --- | --- | --- |
| `--threads INTEGER` | 逻辑 CPU 数量 | `1` 到本机逻辑 CPU 数量 |
| `--resolution-rate FLOAT` | `1.0` | `0.05` 到 `10.0`，对应 Dashboard 的 `5%` 到 `1000%` |
| `--ode-solver TEXT` | `Forward_Euler` | 仅支持 `Forward_Euler` |
| `--step-tolerance FLOAT` | `0.05` | `0.0001` 到 `0.2` |
| `--auto-plot / --no-auto-plot` | 关闭 | 是否实时绘制本地图表 |
| `--force-recalculate / --no-force-recalculate` | 关闭 | 强制重新计算，不允许复用相同设置的结果 |
| `--steady-state / --no-steady-state` | 关闭 | 是否计算稳态 |
| `--platform TEXT` | 安装包对应平台 | `linux`、`windows` 或 `mac`；通常不传 |

## 分析专用参数

| 选项 | 默认值 | 作用 |
| --- | --- | --- |
| `--intensity-oat FLOAT` | `0.01` | OAT 扰动比例，范围 `0.01` 到 `0.1`（`1%` 到 `10%`） |
| `--amount-lhs INTEGER` | `10` | LHS 样本数，至少为 `2` |
| `--amount-ga INTEGER` | `1` | GA/RFGA 并行运行次数，至少为 `1` |
| `--individual-ga INTEGER` | 逻辑 CPU 数量 | 种群数量，至少为 `1`；建议为 `--threads` 的整数倍 |
| `--generation-ga INTEGER` | `200` | 最大迭代代数，至少为 `1` |
| `--escaped-threshold-ga INTEGER` | `100` | 连续多少代没有改善时提前结束，至少为 `1` |
| `--ga-initial-value / --no-ga-initial-value` | 关闭 | 是否使用当前 Variable Value 作为 GA/RFGA 初始值 |
| `--auto-plot-correlation / --no-auto-plot-correlation` | 关闭 | 是否生成 OAT Pearson 相关性数据和图；需要同时开启 `--auto-plot`，且至少有两个 `Evaluation=true` 的参数 |
| `--auto-plot-skeleton / --no-auto-plot-skeleton` | 开启 | 是否自动绘制骨架图 |

### 通用初始化参数

以下参数用于生成初始总体或样本集的算法：

| 选项 | 默认值 | 作用 |
| --- | --- | --- |
| `--initialization-method TEXT` | `LHS` | `UNC`/`LHS`/`GA`/`RFGA`/`SCEUA` 共用：`LHS`、`scrambled_sobol`、`sobol` 或 `uniform`。 |
| `--fixed-initialization-seed / --random-initialization-seed` | 随机 | 为 LHS、Scrambled Sobol 或 Uniform 使用可复现 Seed。未 Scrambling 的 Sobol 是确定性的，不使用 Seed。 |
| `--initialization-seed INTEGER` | `1` | 开启固定 Seed 时使用的正整数，范围 `1` 到 `4294967295`。 |
| `--inject-initial-value / --no-inject-initial-value` | 继承旧 GA 设置 | 对 GA/RFGA/SCE-UA，将 `Solution.Variable.InitialValue` 注入初始总体。 |

### SCE-UA 参数

`SCEUA` 将总体划分为多个 Complex，执行外层 Shuffle。Complex 使用通用的
`--threads` 设置，并可以并行计算。

| 选项 | 默认值 | 作用 |
| --- | --- | --- |
| `--sceua-num-complexes INTEGER` | 自动 | 独立 Complex 的数量。未传入时使用 `min(max(2, --threads), 8)`。 |
| `--sceua-complex-population-size INTEGER` | 不传 | 每个 Complex 的点数；后端默认 `2 × dimension + 1`，最小 `dimension + 1`。 |
| `--sceua-population-size INTEGER` | 不传 | 旧版总总体参数；与每个 Complex 的参数同时传入时必须一致。 |
| `--sceua-subcomplex-size INTEGER` | 自动 | 每个 Complex 在一次临时 Sub-complex 进化步骤中抽取的点数；默认 `dimension + 1`，不能大于每个 Complex 的点数。 |
| `--sceua-evolution-steps INTEGER` | 自动 | 每个 Complex 在一次 Shuffle 中连续执行的 Sub-complex 进化步骤数；默认等于每个 Complex 的点数，至少为 `1`。 |
| `--sceua-max-evaluations INTEGER` | 不传 | 目标函数总计算预算，包括初始化；后端默认 `20 × 总总体`，且至少为总总体。 |
| `--sceua-max-shuffles INTEGER` | `0` | 外层 Shuffle 次数的可选硬上限；`0` 表示不启用这个上限。 |
| `--sceua-convergence-shuffles INTEGER` | `10` | 目标改善不足时连续多少次 Shuffle 后提前停止。 |
| `--sceua-objective-tolerance FLOAT` | `1e-4` | 最优目标的相对改善阈值；大于 `0` 时必须设置收敛 Shuffle。 |
| `--sceua-parameter-tolerance FLOAT` | `1e-4` | 参数总体收缩阈值；`0` 表示关闭。 |

SCE-UA 总总体为 `--sceua-num-complexes × --sceua-complex-population-size`。
普通正式计算使用默认的目标和参数容差。两个提前停止分支是**或**关系：目标函数条件满足，
**或**参数空间条件满足，SCE-UA 就可以提前结束。`Maximum Shuffles` 是外层 Shuffle
次数的可选硬上限，设置为 `0` 时不启用；`Maximum Evaluations` 仍是目标函数计算预算。

每次 Shuffle 中，每个 Complex 按 `Evolution Steps` 连续执行局部进化。每一步从该
Complex 中选择 `Sub-complex Size` 个点组成临时 Sub-complex，接受的新试探点先写回
Complex，然后下一步重新选择 Sub-complex。这两个参数对应算法内部的 NPS 和 NSPL 控制量。

## 启动和等待参数

| 选项 | 默认值 | 作用 |
| --- | --- | --- |
| `--no-launch` | 关闭 | 只准备文件，不启动本机 SimpoClient |
| `--print-protocol` | 关闭 | 在 JSON 中包含带短期凭证的启动协议 |
| `--client-main PATH` | 已安装 SimpoClient | 可选的自定义 SimpoClient 可执行文件或 `main.py` |
| `--wait / --no-wait` | 不等待 | 轮询直到 `completed`、`failed`、`stopped` 或 `idle` |
| `--poll-interval SECONDS` | `2.0` | 等待时两次状态请求的间隔 |
| `--wait-timeout SECONDS` | `86400` | CLI 最长轮询时间；不会停止实际计算 |
| `--timeout SECONDS` | `3700` | 单次后端准备和编译请求的超时时间 |
| `--async-preparation / --no-async-preparation` | 关闭 | 将准备过程放入持久化后端 Operation 队列 |
| `--wait-preparation / --no-wait-preparation` | 关闭 | 异步准备完成后再启动 SimpoClient |
| `--preparation-wait-timeout SECONDS` | `86400` | 等待准备 Operation 的最长时间 |
| `--preparation-poll-interval SECONDS` | `2.0` | 准备状态请求间隔 |
| `--idempotency-key TEXT` | 不传 | 异步准备重试时复用同一 Operation 的稳定键 |
| `--api-token TOKEN` | 已配置 Token | 临时覆盖完整 Token |
| `--base-url URL` | 安装包环境对应的地址 | 仅覆盖本次请求的后端地址 |

`--no-launch` 不能与 `--wait` 同时使用。达到 `--wait-timeout` 时，只是当前
等待中的 CLI 退出，SimpoClient 和计算仍会继续。之后可使用
[`get-calculation-status`](./get-calculation-status) 查询，或使用
[`stop-calculation`](./stop-calculation) 明确停止。

准备过程较长时，可使用 `--async-preparation --no-launch`，保存返回的
`operationId`，再执行 `wait-operation`。如果希望准备完成后由 CLI 自动启动本机
客户端，则使用 `--async-preparation --wait-preparation`。

OAT 的敏感性排序和加权积分结果不等于已经计算了参数相关性。相关性默认关闭；
需要 Pearson 相关系数或 Dashboard 的 Correlation 面板时，必须同时传入：

```text
simpo calculate PROJECT_ID --engine OAT_AR \
  --auto-plot --auto-plot-correlation --wait
```

`--auto-plot-correlation` 单独开启仍可能得到空的 `correlation` 输出，因为客户端
只有在自动绘图也开启时才生成相关性数据。另外，至少需要两个
`Evaluation=true` 的参数；少于两个时没有成对相关系数，空输出是预期行为，不能
解释为“相关系数为 0”。

## DataSet 初始值规则

计算时，`Solution.Variable.Value` 是 `Inflow` 和 `Flow` 的实际基准值。后端会
将它与 DataSet 在 `time=0` 的首值比较，得到差值后加到整列，并将负值截断为
`0`。其中 `Inflow` 需要先按照当前 BioModel/Project Parameter Value 解析选定的
`Conversion` 表达式：

```text
Inflow 平移量 = Variable.Value × Conversion 系数 - DataSet 首值
Flow 平移量   = Variable.Value - DataSet 首值
```

例如，一对一 Conversion 下，Inflow 首值为 `100`、Solution 中的 Value 为
`1000` 时，整列平移 `900`，`[100, 120, 90]` 实际计算为
`[1000, 1020, 990]`。Flow 平移后还会从 `m3/d` 转换为计算使用的 `m3/s`。

这个规则不适用于 `Measured`：Measured 保持原始观测值，用于和模型输出比较，
不能为了匹配 Variable Value 而平移。记录计算时应使用的 DataSet 首值、Solution
Value、原始 Conversion 表达式、解析后的系数和平移量，不要预先修改 DataSet 来
抵消运行时行为。

`--print-protocol` 仅供明确的集成场景使用。启动协议包含短期凭证，不要公开
或写入公共日志。

## 返回结果

没有使用 `--wait` 时，成功只表示文件准备完成并启动了本地客户端，不表示
计算已经完成：

使用 `--wait` 时，`finalStatus` 包含后端最终状态。

```json
{
  "success": true,
  "projectId": 706,
  "projectName": "Example",
  "projectVersion": 0,
  "engine": "SIM",
  "clientPid": 12345,
  "launched": true,
  "launchBeforeSeconds": 3600,
  "finalStatus": null
}
```
