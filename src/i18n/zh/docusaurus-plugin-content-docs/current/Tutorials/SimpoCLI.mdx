# SimpoCLI 命令行使用指南

`SimpoCLI` 是 SIMPO OpenAPI 的命令行客户端，完整支持 BioModel、DataSet 和
Project 的 Draft 新建、更新、同步与发布流程，也可以读取和修改 Project
Variable、准备计算、启动本机安装的 `SimpoClient`、查询或停止计算，并分块读取
可能很大的已保存计算结果。
安装后的终端命令统一为简短的小写 `simpo`。

本页是 SimpoCLI 的完整命令总目录。每个命令也都拆分为独立页面，位于左侧
可折叠的 **SimpoCLI** 目录中。
所有命令也都支持 `--help`，用户或自动化 AI 可以先读取当前安装版本的帮助，
再准确调用命令。

如果使用 AI 编程助手，请先查看 [SIMPO Skill 总览](./SimpoCLI/simpo-skills)，其中汇总
了 Codex 和 Claude Code 的 Skill、调用名称、安装目录以及详情页面。

## 使用条件

- 拥有 SIMPO 账户，并在 Dashboard 的 **API Tokens** 页面创建 OpenAPI
  Token。
- Token 拥有命令要求的最小 scope：
  - `read`：列出和读取自己的 BioModel、DataSet 与 Project，读取 Project
    Variable 的全部字段，以及获取已保存的计算结果；
  - `write`：新建、更新、同步或发布 BioModel、DataSet 与 Project，以及修改
    version 为 `0` 的 Draft Project Variable 字段；
  - `calculate`：准备、查询或停止计算。
- [`calculate`](./SimpoCLI/calculate) 命令还要求同一台电脑上安装对应
  平台版本的 `SimpoClient`。

## 下载和安装

SimpoCLI 与 SimpoClient 相互独立，但是 `calculate` 命令会启动
SimpoClient 执行实际的本地计算。如果这台电脑需要运行计算，应同时安装两个
应用。

- **Linux：**<a href={config.customFields.urlDownloalClientUbuntu} target="_self" rel="noopener noreferrer" download>下载 Debian 安装包</a>。

## 获取个人 API Token

1. 登录 SIMPO Dashboard。
2. 打开 <a href={config.customFields.urlDashApiTokens} target="_blank" rel="noopener noreferrer"><strong>Account → API Tokens</strong></a>。
3. 点击 **Create Token**。
4. 输入便于识别的名称，设置 `1` 到 `365` 天的有效期，并且只选择需要的
   scope：
   - `read`：用于全部 `get-*` 命令，包括分块读取计算结果；
   - `write`：用于 BioModel、DataSet、Project 的新建、更新、同步、发布命令，
     以及 `set-project-variable`；
   - `calculate`：用于准备计算、查询状态和停止计算。
5. 点击 **Create Token**，然后在 **Token Created** 弹窗中立即复制完整
   Token。

:::warning 立即复制完整 Token

出于安全原因，完整 Token 只显示一次。之后列表中只能看到 `tokenPrefix`，
它不能用于 API 认证。如果完整 Token 丢失，请撤销旧 Token 并重新创建。
Dashboard 登录 JWT 也不能作为 OpenAPI Token 使用。

:::

## 配置并验证 Token

访问 Project 前，保存刚才复制的个人 Token 并完成验证：

```text
simpo configure
simpo me
```

如需只删除已保存的 API Token、保留 CLI 数据目录，可运行：

```text
simpo logout
```

Token 查找顺序为：

1. 当前命令的 `--api-token`；
2. `SIMPO_API_TOKEN` 环境变量；
3. 当前用户的 `SIMPO_API_TOKEN.json` 文件。

Linux 保存路径为 `~/.SimpoCLI/SIMPO_API_TOKEN.json`，Windows 保存路径
为 `%APPDATA%\SimpoCLI\SIMPO_API_TOKEN.json`。文件中包含完整 Token，
必须妥善保护。

完整配置过程请查看 [`configure`](./SimpoCLI/configure)。

## 命令索引

所有资源遵循同一基本规则：编辑 version `0` Draft，将已发布的 Release
作为不可修改快照，并使用 `sync-*` 将 Release 复制回 Draft。关联 Project
重建和计算结果失效规则已写在对应的更新命令页面中。下面的表格是完整命令目录。

### Token

| 命令 | 功能 | 所需 scope |
| --- | --- | --- |
| [`configure`](./SimpoCLI/configure) | 验证并保存 OpenAPI Token | 本地写入不需要 scope，但 Token 验证必须成功 |
| [`me`](./SimpoCLI/me) | 验证 Token，并显示身份和 scope | 有效 Token |
| [`logout`](./SimpoCLI/logout) | 删除本地保存的 Token 文件，但不会撤销服务器 Token | 无 |

### BioModel

| 命令 | 功能 | 所需 scope |
| --- | --- | --- |
| [`create-biomodel`](./SimpoCLI/create-biomodel) | 新建空白、Excel 或 JSON Draft BioModel | `write` |
| [`get-biomodels`](./SimpoCLI/get-biomodels) | 列出自己的 BioModel 元数据 | `read` |
| [`get-biomodel`](./SimpoCLI/get-biomodel) | 读取一个 BioModel 及其完整模型表格 | `read` |
| [`update-biomodel`](./SimpoCLI/update-biomodel) | 替换 version `0` Draft BioModel 的模型表 | `write` |
| [`sync-biomodel`](./SimpoCLI/sync-biomodel) | 将自己的 Release/Standard 版本复制到同名 Draft | `write` |
| [`release-biomodel`](./SimpoCLI/release-biomodel) | 从 version `0` Draft 创建下一个不可修改的 Release | `write` |

### DataSet

| 命令 | 功能 | 所需 scope |
| --- | --- | --- |
| [`create-dataset`](./SimpoCLI/create-dataset) | 新建空白或 JSON Draft DataSet | `write` |
| [`get-datasets`](./SimpoCLI/get-datasets) | 列出自己的 DataSet 元数据 | `read` |
| [`get-dataset`](./SimpoCLI/get-dataset) | 读取一个 DataSet 及其完整模型表格 | `read` |
| [`update-dataset`](./SimpoCLI/update-dataset) | 替换 Draft DataSet，并重建关联 Project | `write` |
| [`sync-dataset`](./SimpoCLI/sync-dataset) | 将自己的 Release 复制到同名 Draft | `write` |
| [`release-dataset`](./SimpoCLI/release-dataset) | 从 Draft 创建不可修改的 Release | `write` |

### Project

| 命令 | 功能 | 所需 scope |
| --- | --- | --- |
| [`create-project`](./SimpoCLI/create-project) | 使用 BioModel 和 DataSet 新建 Draft，可同时提供 Solution JSON | `write` |
| [`get-projects`](./SimpoCLI/get-projects) | 列出自己的 Project 元数据及 BioModel/DataSet 引用 | `read` |
| [`get-project`](./SimpoCLI/get-project) | 读取一个 Project 及其完整 Solution detail | `read` |
| [`update-project`](./SimpoCLI/update-project) | 替换 Draft Project 的 Solution detail | `write` |
| [`sync-project`](./SimpoCLI/sync-project) | 将自己的 Release 复制到对应 Draft | `write` |
| [`release-project`](./SimpoCLI/release-project) | 创建不可修改的 Project Release | `write` |
| [`get-project-variables`](./SimpoCLI/project-variables) | 读取 Solution Variable 表的全部字段 | `read` |
| [`set-project-variable`](./SimpoCLI/set-project-variable) | 修改 Draft Project 中一个 Variable 字段 | `write` |

### Calculation

| 命令 | 功能 | 所需 scope |
| --- | --- | --- |
| [`calculate`](./SimpoCLI/calculate) | 准备计算并启动 SimpoClient | `calculate` |
| [`get-calculation-status`](./SimpoCLI/get-calculation-status) | 查询当前计算状态 | `calculate` |
| [`get-calculation-result`](./SimpoCLI/calculation-result) | 导航并分块读取已保存的计算结果，避免无限制响应 | `read` |
| [`stop-calculation`](./SimpoCLI/stop-calculation) | 停止计算和匹配的本地进程 | `calculate` |

## 输出约定

- 成功结果以格式化 JSON 写入 **stdout**。
- 进度提示和错误写入 **stderr**。
- 退出码 `0` 表示成功；非零退出码表示命令失败。
- HTTP 错误包含状态码和安全的后端消息。`401` 通常表示 Token 无效、过期、
  被撤销或与后端环境不匹配；`403` 表示缺少所需 scope。

因此自动化脚本可以只解析 stdout：

```bash
result="$(simpo get-project-variables 706)" || exit $?
printf '%s\n' "$result"
```

`--base-url` 只建议用于单次开发环境覆盖，例如：

```text
simpo me --base-url http://127.0.0.1:8888
```

Token 必须属于当前选择的后端环境。
