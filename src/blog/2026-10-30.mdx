In this major release, we have deeply refined our underlying calculation logic—not only upgrading the calculation modes to three distinct options, but also significantly optimizing steady-state calculations. Meanwhile, Chinese language support for **SimpoDash** is finally here!

## Upgraded Calculation Modes & One-Click Reuse of Steady-State Results

Simpo now offers three powerful calculation modes for you to choose from:
* **Dynamic**: Classic dynamic simulation.
* **Steady-State**: Pure steady-state simulation.
* **Steady-State Dynamic**: Dynamic simulation using the steady-state solution directly as initial values—say goodbye to tedious initial value tuning!

Once a **Steady-State** or **Steady-State Dynamic** calculation is completed, the system automatically generates comprehensive steady-state results, including key metrics such as **Components**, **HRT**, and **SRT**. Furthermore, the **Component** values derived from steady-state calculations can now be written directly to **Variables** with a single click via **SetToValue**.

---

## More Scientific Averaging for Steady-State Inputs

To ensure the accuracy of steady-state simulation inputs, version 1.5.0 refactors the averaging logic for time series data:

* **Step 1: Baseline Offset Calibration**
  - The system first shifts the entire time series based on the difference between `Solution.Variable` and the original `DataSet`.
  - For example: if a Flow in Variable is set to 100, while the corresponding value in DataSet is 10, the entire flow series will be shifted upward by 90.

* **Step 2: Flexible Time Series Interpolation**
  - Pre-processes the original series via `steady_state_input_average_method`, supporting three interpolation modes:
    * `previous` (Default): Forward fill using the previous value
    * `linear`: Linear interpolation
    * `arithmetic`: Simple row average

* **Step 3: Category-Specific Weighted Calculation**
  * **Flow**: Uses a step average weighted by time intervals, i.e., `Q_avg = ∑(Qi × Δti) / ∑Δti`.
  * **Inflow**: If a corresponding Flow exists, it automatically applies a more scientific **flow-weighted average**, i.e., `C_avg = ∑(Ci × Qi × Δti) / ∑(Qi × Δti)`.
  * **Measured**: Optimized to use the **arithmetic mean** (replacing the previous approach of only using the first and last rows).

## Comprehensive UX & Under-the-Hood Optimizations

* **New `Constraint` Page**: In `Project.Solution`, you can now enforce a fixed value for a specific Component within a given Tank. This is ideal for **locking modeled Dissolved Oxygen (DO) directly to actual measured values**.
* **New `Formula` Page**: In `BioModel`, you can now directly define the calculation method for a specific component (typically **TSS**) using algebraic formulas. This not only prevents components calculated via coefficients from interfering with initial values, but also boosts overall calculation speed.
* **New `Retention` Page**: In `Solution`, you can freely select which Tanks participate in the system's `HRT` and `SRT` calculations, making retention time accounting for complex process configurations crystal clear.
* **One-Click Line Chart Toggle for Measured Points**: Visual comparisons are now more intuitive. Measured points in result charts can now be toggled to a **line chart mode** with a single click (or press the `Spacebar` for a quick toggle).
* **Bilingual Support in SimpoDash**: SimpoDash now fully supports a Chinese interface, allowing seamless, one-click switching between English and Chinese.
* **Upgraded Standard Target Identification**: Added a `StandardTarget` column to the Target table in `DataSet` to accurately identify which targets correspond to `Dissolved Oxygen` and `Total Suspended Solids`. The legacy DO column has been removed for a cleaner data structure.
* **Interaction Upgrade**: Newly optimized user interaction experience on the Console page.
* **Algorithm Improvement**: Further optimized the termination criteria for steady-state calculations.
* **Architecture Upgrade**: Upgraded the backend authentication mechanism to a more secure and stable `session` mode.
* **Bug Fix**: Fixed an issue with the Balance calculation order; it now correctly occurs before the shifting of kinetic parameters.
